VGA Color Compare Register in Pixel Collision Detection

This article examines how classic PC game developers utilized the Video Graphics Array (VGA) hardware Color Compare register to accelerate pixel-level collision detection. By offloading complex multi-plane bitwise evaluations directly to the VGA Graphics Controller, games running on resource-constrained CPUs could detect boundary hits and object overlaps in a fraction of the standard processing time.

The Challenge of Planar Memory

In standard planar VGA display modes (such as 640x480 16-color Mode 12h or unchained 256-color Mode X), pixel data is distributed across four distinct memory planes rather than stored contiguously. Determining the color of a single pixel using standard operations requires reading each of the four planes sequentially, latching the data, and reconstructing the color index using CPU-intensive bit-shifting and masking routines. In fast-paced games where dozens of bounding boxes or complex sprite masks must be verified every frame, performing software-based pixel checks quickly saturates the CPU bus.

The Role of Read Mode 1

The VGA Graphics Controller provides specialized hardware read modes to mitigate this bottleneck. While Read Mode 0 performs standard byte reads, Read Mode 1 transforms screen reads into automated parallel comparisons.

To use this feature, the game programmer configures two specific registers in the VGA Graphics Controller:

  1. Color Compare Register (Index 02h): Holds the specific color index (0–15 in 16-color modes) being tested, such as the color of a solid wall, obstacle, or transparent background.
  2. Color Don't Care Register (Index 07h): Designates which bitplanes should be included in or excluded from the comparison.

Hardware-Accelerated Bitmask Generation

When the CPU reads a single byte from display memory while in Read Mode 1, the VGA hardware executes a comparison across all four internal latches simultaneously. For each of the eight horizontal pixels represented by the memory address, the hardware checks if the pixel's color matches the value in the Color Compare register.

Instead of returning pixel data, the read operation returns a single 8-bit byte directly to the CPU:

  • A bit is set to 1 if the corresponding pixel matches the Color Compare register.
  • A bit is set to 0 if the pixel does not match.

Implementing Rapid Collision Detection

This hardware mechanism drastically simplifies collision routines. To check if a moving entity collides with a background obstacle:

  1. The developer sets the Color Compare register to the color value assigned to impenetrable terrain.
  2. The controller is placed into Read Mode 1.
  3. The CPU reads the display memory addresses corresponding to the bounding box of the entity. Each read immediately yields an 8-pixel collision mask generated by the VGA silicon.
  4. The CPU performs a single bitwise AND operation between the returned byte and the entity's own 1-bit transparency or collision mask.
  5. If the result is non-zero, a pixel-perfect collision has occurred.

By eliminating the need to manually extract individual plane bits, the Color Compare register compresses dozens of CPU instructions into a single memory read and a single logical operation, enabling smooth, pixel-accurate collision detection on vintage hardware.
