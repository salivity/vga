VGA CRT Pixel Aspect Ratio Hardware Calculation

This article explains the hardware-level calculations used to determine the Pixel Aspect Ratio (PAR) on an analog 4:3 Video Graphics Array (VGA) cathode-ray tube (CRT) monitor. It covers the mathematical relationship between physical screen geometry, display timings, dot clock frequency, and active raster dimensions, demonstrating how video hardware maps digital pixel buffers onto continuous analog scanlines.

The Underlying Physics of CRT Displays

Unlike modern LCDs with fixed physical pixel grids, a CRT draws images using continuous analog electron beams deflected across a phosphor-coated screen. Vertically, the display is divided into discrete scanlines dictated by the horizontal sweep frequency. Horizontally, there are no physical hardware pixels; horizontal pixels are defined purely by time intervals during which the video digital-to-analog converter (RAMDAC) outputs a voltage level.

Because deflection coils are calibrated to sweep the active raster across a physical faceplate with a standard 4:3 Display Aspect Ratio (DAR), the physical width-to-height ratio of the visible screen area is:

\[\text{DAR} = \frac{W_{\text{physical}}}{H_{\text{physical}}} = \frac{4}{3} \approx 1.333\]

The Fundamental PAR Calculation

The Pixel Aspect Ratio (PAR) represents the ratio of the physical width (\(W_p\)) to the physical height (\(H_p\)) of an individual displayed pixel:

\[\text{PAR} = \frac{W_p}{H_p}\]

Given that the total active physical width is divided by the number of active horizontal pixels (\(H_{\text{pixels}}\)), and the total active physical height is divided by the number of active vertical lines (\(V_{\text{lines}}\)):

\[W_p = \frac{W_{\text{physical}}}{H_{\text{pixels}}}\]

\[H_p = \frac{H_{\text{physical}}}{V_{\text{lines}}}\]

Substituting these into the PAR equation gives the standard calculation:

\[\text{PAR} = \left(\frac{W_{\text{physical}}}{H_{\text{physical}}}\right) \times \left(\frac{V_{\text{lines}}}{H_{\text{pixels}}}\right) = \frac{4}{3} \times \frac{V_{\text{lines}}}{H_{\text{pixels}}}\]

Derivation via Video Timing Hardware

At the hardware level, active resolution is controlled by the Cathode Ray Tube Controller (CRTC) and the pixel clock (dot clock).

1. Horizontal Pixel Width Calculation

The horizontal dimension of a pixel depends on the dot clock frequency (\(f_{\text{dot}}\)) and the horizontal sweep velocity (\(v_h\)).

  • Dot Clock Period (\(t_{\text{pixel}}\)): \(t_{\text{pixel}} = \frac{1}{f_{\text{dot}}}\)
  • Active Line Time (\(T_{\text{active\_h}}\)): \(T_{\text{active\_h}} = H_{\text{pixels}} \times t_{\text{pixel}} = \frac{H_{\text{pixels}}}{f_{\text{dot}}}\)
  • Physical Beam Speed (\(v_h\)): \(v_h = \frac{W_{\text{physical}}}{T_{\text{active\_h}}}\)

Thus, physical pixel width is determined directly by:

\[W_p = v_h \times t_{\text{pixel}} = \frac{W_{\text{physical}}}{H_{\text{pixels}}}\]

2. Vertical Pixel Height Calculation

The vertical height depends on the number of discrete scanlines drawn during the vertical refresh period:

\[H_p = \frac{H_{\text{physical}}}{V_{\text{lines}}}\]

Where \(V_{\text{lines}}\) represents the active scanlines programmed into the CRTC vertical registers (excluding vertical blanking intervals).

Standard VGA Mode Examples

Standard 640x480 Mode (Square Pixels)

In classic VGA 640×480 @ 60 Hz mode:

  • \(H_{\text{pixels}} = 640\)
  • \(V_{\text{lines}} = 480\)
  • \(f_{\text{dot}} \approx 25.175\text{ MHz}\)

\[\text{PAR} = \frac{4}{3} \times \frac{480}{640} = \frac{4}{3} \times \frac{3}{4} = 1.0\]

The result is a \(1:1\) ratio, meaning pixels are perfectly square.

Mode 13h: 320x200 Mode (Non-Square Pixels)

In standard 320×200 gaming modes:

  • \(H_{\text{pixels}} = 320\)
  • \(V_{\text{lines}} = 200\)

\[\text{PAR} = \frac{4}{3} \times \frac{200}{320} = \frac{4}{3} \times \frac{5}{8} = \frac{5}{6} \approx 0.833\]

In this hardware configuration, the pixels are vertically elongated (taller than they are wide) with a width-to-height ratio of \(5:6\).
