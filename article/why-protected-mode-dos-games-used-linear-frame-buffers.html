Why Protected Mode DOS Games Used Linear Frame Buffers

During the mid-1990s, the transition to 32-bit protected-mode DOS extenders revolutionized PC gaming by unlocking gigabytes of addressable memory. However, graphical performance remained throttled by legacy video architectures until the adoption of the Linear Frame Buffer (LFB). By mapping the entire video memory into a single, contiguous address space, an LFB eliminated the severe CPU bottlenecks associated with legacy bank switching. This synergy between 32-bit protected mode and direct VESA video access allowed developers to render high-resolution Super VGA (SVGA) graphics at playable frame rates.

The Bottleneck of Legacy Bank Switching

Standard IBM VGA hardware allocated a 128 KB memory window between physical addresses 0xA0000 and 0xBFFFF, with graphics modes typically restricted to a 64 KB aperture at 0xA0000. This architecture was sufficient for standard Mode 13h (320×200 at 8-bit color, requiring only 64,000 bytes).

As displays shifted toward SVGA resolutions, the 64 KB window became a critical bottleneck:

  • A 640×480 display at 8-bit color requires 307,200 bytes—roughly five 64 KB segments.
  • To write an entire frame, the software had to split the display memory into "banks" or "pages."
  • Whenever a draw routine crossed a 64 KB boundary, the program had to execute a bank switch, either by calling VESA BIOS interrupt INT 10h, AX=4F05h or by directly writing to hardware I/O ports on the graphics card.

These bank-switching operations stalled the CPU pipeline, required complex branching logic inside inner rasterization loops, and severely degraded rendering throughput.

How Protected-Mode Extenders Altered the Architecture

Real-mode DOS operated within a 1 MB address space restricted to 16-bit segmented addressing (segment:offset). DOS extenders (such as DOS/4GW, Causeway, and PMODE/W) leveraged the protected mode of Intel 80386 and newer processors.

Protected mode offered two major features:

  1. Flat 32-bit Addressing: The CPU could address up to 4 GB of memory directly using single 32-bit pointers, eliminating the need to manipulate segment registers.
  2. Paging and Memory Mapping: The operating environment could map arbitrary physical addresses anywhere within a program's virtual address space.

While protected mode solved system memory constraints for game assets, games initially still had to interact with video cards through the 16-bit real-mode VESA BIOS or manipulate the cramped 64 KB aperture at 0xA0000.

The Linear Frame Buffer Advantage

Standardized primarily through VESA BIOS Extension (VBE) 2.0, the Linear Frame Buffer resolved this mismatch. Instead of forcing video access through the 64 KB real-mode window below the 1 MB mark, the graphics card mapped its entire onboard VRAM (typically 1 MB to 4 MB or more) into an unsegmented physical address space located high in the 32-bit memory map (often above 2 GB or just below the top of physical RAM).

With an LFB, protected-mode games gained several immediate advantages:

  • Elimination of Bank Switching: The entire screen buffer was visible at once. Developers no longer needed conditional checks to detect if a horizontal scanline or a polygon crossed a 64 KB boundary.
  • Direct Pointer Arithmetic: Calculating a pixel's memory location simplified to a base address plus an offset: VideoMemory + (y * Pitch) + x. This allowed inner drawing loops for 3D software rasterizers to run entirely within registers.
  • Optimized Block Transfers: Off-screen buffers rendered in system RAM could be transferred directly to the display using fast x86 string instructions (such as REP MOVSD) or unrolled loops, maximizing PCI and VLB (VESA Local Bus) bus bandwidth.
  • Support for True Color and High Resolutions: As 16-bit (65,536 colors) and 24-bit/32-bit color modes emerged, a single frame easily exceeded 1 MB. An LFB made these color-rich modes mathematically viable for software renderers.

By pairing 32-bit flat-model execution with a Linear Frame Buffer, developers removed the hardware-imposed segmentation of the 1980s, enabling titles like Quake, Duke Nukem 3D, and Descent II to achieve fast, high-resolution rendering during the final era of DOS gaming.
