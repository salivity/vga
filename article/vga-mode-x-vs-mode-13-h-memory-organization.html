VGA Mode X vs Mode 13h: Memory Organization

This article examines how IBM's standard VGA Mode 13h and the programmer-tweaked Mode X differ in their underlying video memory architectures. While standard Mode 13h offers a simple, linear framebuffer that limits the developer to a single 64 KB window, Mode X unchains the VGA hardware to expose four parallel memory planes. Understanding this architectural shift highlights how Mode X overcomes the limitations of Mode 13h to provide access to all 256 KB of video RAM, multi-buffering, and accelerated graphics operations.

Linear (Chained) vs. Planar (Unchained) Addressing

The defining difference between the two modes lies in how the VGA sequencer maps CPU memory addresses to physical video RAM:

  • Mode 13h (Chained / Chain-4 Mode): Mode 13h configures the VGA hardware in "Chain-4" mode. The internal hardware interleaves bytes across the VGA’s four physical memory planes automatically: address 0 goes to Plane 0, address 1 to Plane 1, address 2 to Plane 2, address 3 to Plane 3, address 4 to Plane 0, and so on. To the CPU, this presents a simple, contiguous 64 KB linear block starting at 0xA000:0000. A pixel at coordinate (x, y) corresponds directly to memory offset (y * 320) + x.

  • Mode X (Unchained Mode): Mode X disables the Chain-4 bit in the Sequencer's Memory Mode register (0x3C5, index 0x04). This removes the automatic hardware interleaving and reveals the true planar structure of the VGA hardware. The four memory planes now occupy the exact same 64 KB address space (0xA000:0000 to 0xA000:FFFF). A byte at address offset in CPU memory exists simultaneously on Plane 0, Plane 1, Plane 2, and Plane 3. A pixel at (x, y) resides in Plane (x mod 4) at the memory offset (y * 80) + (x / 4).

Accessible Video Memory

  • Mode 13h: Because the CPU can only view 64 KB through the chained mapping mechanism, Mode 13h can only utilize 64,000 bytes out of the 262,144 bytes (256 KB) present on standard VGA cards. The remaining 192 KB remains inaccessible to the CPU, leaving just enough memory for a single 320×200 8-bit frame with no room for off-screen buffering.

  • Mode X: By switching to planar addressing, the CPU gains direct access to all four 64 KB planes individually, unlocking the full 256 KB of VGA memory. At the standard Mode X resolution of 320×240 (or even 320×200), a single screen frame consumes only 19,200 bytes per plane (76,800 bytes total). This leaves enough space to store up to three full 320×240 display pages or four 320×200 pages directly in video memory.

Page Flipping and Off-Screen Storage

  • Mode 13h: With only one screen buffer fitting within the accessible 64 KB, developers must perform animations either directly on the visible screen—often introducing visual tearing—or compose frames in system RAM and copy them via the slow ISA bus during the vertical retrace interval.

  • Mode X: Because the full 256 KB is accessible, developers can maintain multiple framebuffers in video RAM simultaneously. Smooth, tear-free animation is achieved via hardware page flipping: while the monitor displays one page, the CPU draws to an off-screen page, and the CRTC Start Address registers (0x3D4, indices 0x0C and 0x0D) are updated to immediately swap the visible buffer during the vertical blanking interval. Unused video memory can also store sprites or tile graphics for fast copying.

CPU Read and Write Operations

  • Mode 13h: Reading and writing pixels requires minimal overhead. A single 8-bit CPU write puts a pixel on the screen, and standard linear pointer arithmetic applies. However, the CPU can only write one pixel per operation.

  • Mode X: To target a pixel, the CPU must specify which plane to access:

    • Writing: The CPU configures the VGA Map Mask register (0x3C5, index 0x02) to enable one or more planes. While this adds overhead for drawing single scattered pixels, it enables hardware acceleration: by enabling all four planes simultaneously, a single 8-bit CPU write modifies four horizontal pixels at once, effectively quadrupling fill and clear speeds.
    • Reading: The CPU must set the Read Map Select register (0x3CE, index 0x04) to choose which specific plane to read from before querying a byte.

Resolution and Pixel Aspect Ratio

While not strictly an internal memory mapping difference, Mode X alters the CRT controller timings to deliver a resolution of 320×240 instead of 320×200. Because 320×240 matches the 4:3 physical aspect ratio of standard monitors, Mode X produces square pixels, eliminating the geometry distortion and scaling math inherent to Mode 13h's rectangular pixels.
