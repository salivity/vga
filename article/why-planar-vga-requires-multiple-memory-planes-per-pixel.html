Why Planar VGA Requires Multiple Memory Planes per Pixel

Drawing a single pixel in the classic 16-color planar Video Graphics Array (VGA) mode required interacting with multiple memory planes because the display adapter organized video memory by bit planes rather than contiguous pixel data. In standard 16-color modes, such as Mode 12h (640x480), each pixel is defined by a 4-bit index, and each of those four bits resides in an entirely separate physical memory bank. Consequently, altering the color of a single pixel often required the system to read and update corresponding bit positions across up to four distinct memory planes.

The 4-Bit Color Model and Planar Architecture

In a 16-color palette system, each pixel requires 4 bits of data (\(2^4 = 16\) possible colors). In modern "packed-pixel" architectures, these 4 bits would sit adjacent to one another within a single byte of system memory. A single memory write could easily update one or two adjacent pixels at once.

VGA's planar architecture, inherited from the earlier Enhanced Graphics Adapter (EGA), works differently. Instead of grouping all bits for a single pixel together, VGA divides memory into four parallel 64 KB banks called Plane 0, Plane 1, Plane 2, and Plane 3:

  • Plane 0 holds Bit 0 (the least significant bit) of every pixel.
  • Plane 1 holds Bit 1 of every pixel.
  • Plane 2 holds Bit 2 of every pixel.
  • Plane 3 holds Bit 3 (the most significant bit) of every pixel.

Within any given plane, eight horizontal pixels are grouped into a single byte. Bit 7 of a byte in each plane represents pixel 0, bit 6 represents pixel 1, and so forth.

Why One Pixel Spans Multiple Planes

To assign a pixel a specific color index—such as color 13, which is 1101 in binary—the corresponding bit across all four planes must match that binary representation:

  • Bit in Plane 0 must be set to 1
  • Bit in Plane 1 must be set to 0
  • Bit in Plane 2 must be set to 1
  • Bit in Plane 3 must be set to 1

Because each of these bits is located in a physically distinct memory plane, changing that single pixel requires modifying the memory state in Plane 0, Plane 1, Plane 2, and Plane 3.

The Memory Mapping Bottleneck

The IBM PC architecture mapped video memory to a single segment in the CPU's address space, typically at address 0xA0000. All four memory planes shared this exact same base memory address. The CPU could not simply write a 32-bit value to update all four planes at once using standard memory operations.

Instead, the programmer or the VGA controller had to manage the write process through VGA hardware registers:

  1. Map Mask Register: The CPU used the Map Mask register to enable or disable specific planes before performing a write operation.
  2. Bit Mask Register: Because an entire byte in a plane controls eight different pixels, changing only one pixel required masking out the other seven pixels to prevent them from being overwritten.
  3. Read-Modify-Write Cycles: Unless using specialized VGA hardware write modes, the CPU had to read the existing byte from a plane into internal latches, apply the bitmask, combine it with the new pixel bit, and write the byte back out.

To draw a single pixel with a distinct color, this process had to be repeated or configured across the targeted planes.

Why Planar Memory Was Used

This architecture was chosen to solve the hardware and bandwidth limitations of the late 1980s. By arranging memory into four parallel planes, the VGA display circuitry could read 8 bits from all four planes simultaneously across a wide internal bus. This allowed the display controller to fetch 32 bits of video data (8 complete 4-bit pixels) in a single memory cycle. This high-throughput access was necessary to refresh high-resolution CRTs at 60 Hz without saturating the relatively slow ISA bus of host computers. While it maximized scanout efficiency for the display hardware, it made individual pixel manipulation on the CPU side complex and computationally intensive.
