VGA Hardware Scrolling in Mode X vs Mode 13h

During the MS-DOS era of PC gaming, achieving smooth, full-screen scrolling was a major technical hurdle. While standard VGA Mode 13h was beloved for its simple, linear memory addressing, it severely restricted hardware-accelerated scrolling due to memory size constraints and rigid architecture. By contrast, Mode X—an undocumented, planar tweak of the standard VGA subsystem popularized by Michael Abrash—unlocked the full 256 KB of video RAM, gave access to internal hardware panning registers, and allowed multiple off-screen display buffers. This fundamental shift from linear to planar video memory made hardware scrolling vastly more efficient and easier to implement in Mode X than in Mode 13h.

The Linear Limitations of Mode 13h

Mode 13h provides a 320x200 display resolution with 256 colors. Its primary advantage was its linear frame buffer: each pixel corresponded to a single byte in memory, mapped sequentially from address 0xA000:0000 to 0xA000:FA00. This made drawing individual shapes and pixels straightforward.

However, this simplicity introduced critical drawbacks for scrolling:

  1. Memory Ceiling (The 64 KB Boundary): Mode 13h was configured by the BIOS in a "chained" mode, mapping four internal memory planes into a single linear window limited to roughly 64 KB. Because a single 320x200 screen consumes 64,000 bytes, practically all available memory was used just to display one frame. There was no spare video RAM to store off-screen map boundaries or create an off-screen back buffer for page-flipping.
  2. Heavy CPU Overhead: To scroll in Mode 13h, developers had to manipulate memory manually using the CPU. Scrolling left, right, up, or down required reading and writing nearly the entire 64 KB buffer over the slow ISA bus every frame (a "software blit"). This choked the system bus and left minimal CPU cycles for game logic, physics, or sprite rendering.

How Mode X Unlocked Hardware Scrolling

Mode X altered the VGA hardware registers to disable "chaining" (specifically bit 3 of the Sequence Memory Mode register) and adjust the CRT Controller (CRTC). This returned the VGA to its native planar architecture while retaining 256-color support. This shift provided the essential building blocks for hardware scrolling:

1. Access to the Full 256 KB of VRAM

By unchaining the memory planes, Mode X exposed all four 64 KB planes simultaneously, providing the full 256 KB of video memory. In planar mode, four consecutive horizontal pixels are distributed across the four planes at the exact same memory offset. Because 320x200 pixels now required only 16,000 bytes of addressing space per plane, developers suddenly had room for multiple virtual display screens in VRAM simultaneously. A larger virtual map (for example, 640x400 or 320x800) could reside directly in video memory.

2. The CRTC Start Address Register (Coarse Scrolling)

The VGA CRTC includes a Start Address register (ports 0x3D4 index 0x0C and 0x0D). This 16-bit register tells the VGA raster gun where in VRAM to begin reading display data for the top-left corner of the monitor.

In Mode X, scrolling across multiple tiles or scanlines was instantaneous. By writing a new offset to the Start Address register during the vertical blanking interval, the viewport shifted horizontally (in 4-pixel increments) or vertically (in 1-pixel increments) with zero pixel copying. The CPU did not have to touch the existing screen data; it merely moved a memory pointer.

3. Horizontal PEL Panning (Fine Scrolling)

While the CRTC Start Address register could scroll vertically pixel-by-pixel, horizontal shifts occurred in 4-pixel steps due to the 4-plane architecture. To make horizontal motion completely fluid, Mode X utilized the VGA Attribute Controller's Horizontal PEL Panning Register (port 0x3C0 index 0x13).

This register instructs the VGA pixel serializer to delay rendering by 0, 1, 2, or 3 pixel clocks. Combining the coarse 4-pixel shifts from the CRTC Start Address with the fine 0-to-3 sub-byte shifts of the Horizontal PEL Panning register allowed games to pan horizontally across the screen one individual pixel at a time at full frame rates.

4. Tear-Free Double Buffering and Tile Updates

Because Mode X left roughly 192 KB of VRAM unused by the primary screen, programmers could define a visible buffer and one or more off-screen working buffers.

As the display scrolled, the CPU only needed to draw new incoming columns or rows of tiles onto the off-screen perimeter rather than rewriting the entire screen. Once the new data was in place, the developer updated the Start Address to point to the new buffer during vertical retrace, completely eliminating visual screen tearing and flickering without needing complex software synchronization.
