VGA Write Mode 0 in Planar Memory Explained

VGA Write Mode 0 is the default and most versatile writing mechanism used in IBM-compatible VGA planar graphics modes, such as Mode 12h. This article breaks down the exact hardware pipeline that a byte sent by the CPU undergoes before it updates video RAM. It covers data rotation, the Set/Reset mechanism, logical ALU combining with internal latches, and the final masking stages across the four parallel memory planes.

Step 1: Data Rotation

When the CPU executes a memory write instruction to the VGA memory space (typically segment 0xA000), the 8-bit CPU data byte first enters the Graphics Controller. It passes through the Data Rotate register (part of Graphics Controller register 03h). The hardware rotates the data right by the number of bits (0 to 7) configured in this register. This rotation facilitates quick horizontal bit alignment without requiring multiple CPU shifting instructions.

Step 2: The Set/Reset Mechanism

After rotation, the data branches toward the four individual memory planes (Planes 0 through 3). The hardware checks the Enable Set/Reset register (Graphics Controller register 01h) for each plane:

  • If the Enable Set/Reset bit for a plane is disabled (0), the rotated CPU data byte is passed forward to that plane.
  • If the Enable Set/Reset bit for a plane is enabled (1), the CPU data byte is completely discarded for that plane. In its place, the hardware expands the single-bit value defined for that plane in the Set/Reset register (Graphics Controller register 00h) into an 8-bit byte (0x00 if the bit is 0, or 0xFF if the bit is 1).

Step 3: ALU Operation and Internal Latches

Each plane possesses an internal 8-bit latch, which holds the 8 bits of data read from that specific plane during the most recent CPU memory read operation.

The data stream for each plane (whether from the rotated CPU byte or the Set/Reset logic) meets the plane's internal latch at the Arithmetic Logic Unit (ALU). The Function Select bits within the Data Rotate register specify one of four logical operations:

  • Replace (NOP): The incoming data passes through unchanged.
  • AND: The incoming data is bitwise ANDed with the byte stored in the latch.
  • OR: The incoming data is bitwise ORed with the byte stored in the latch.
  • XOR: The incoming data is bitwise XORed with the byte stored in the latch.

Step 4: Bit Masking

The output of the ALU operation reaches the Bit Mask register stage (Graphics Controller register 08h). The Bit Mask register contains an 8-bit pattern that applies uniformly across all four planes:

  • For any bit set to 1, the corresponding bit from the ALU output is selected.
  • For any bit set to 0, the corresponding bit from the plane's internal latch is selected, leaving that specific pixel component unaltered.

Step 5: Map Masking and Plane Write

Before the final byte is written to physical video memory, the Sequencer's Map Mask register (Sequencer register 02h) determines which of the four memory planes are enabled for writing:

  • If a plane's bit in the Map Mask is enabled (1), the generated byte is committed to that plane at the requested memory offset.
  • If a plane's bit in the Map Mask is disabled (0), the memory in that plane remains completely untouched.

Through this multi-stage pipeline, a single CPU byte write in Write Mode 0 can simultaneously rotate data, apply color expansion, perform logical blending with background memory, and selectively alter individual pixels across all four video planes.
