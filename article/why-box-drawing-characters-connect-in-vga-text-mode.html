Why Box-Drawing Characters Connect in VGA Text Mode

In the classic 720x400 Video Graphics Array (VGA) text mode, box-drawing characters appear continuous because the graphics hardware automatically duplicates the eighth pixel column into the ninth pixel column for specific character codes. While the text grid uses a 9x16 pixel character cell, the stored font data is only 8 pixels wide. To prevent visible vertical gaps in frames and borders, the VGA controller includes dedicated hardware logic that extends horizontal lines across the extra column instead of inserting blank background space.

The 9-Dot Pixel Cell Dilemma

Standard VGA text mode displays 80 columns by 25 rows of text at a total resolution of 720x400 pixels. Dividing these dimensions reveals the cell size allocated to each character:

  • Horizontal: 720 pixels / 80 columns = 9 pixels per cell
  • Vertical: 400 pixels / 25 rows = 16 pixels per cell

However, standard IBM PC fonts stored in the VGA BIOS ROM are designed around an 8x16 pixel grid. This size kept fonts memory-efficient and backward-compatible with earlier standards like EGA and CGA.

To bridge the difference between the 8-pixel-wide font glyph and the 9-pixel-wide display cell, the VGA sequencer generates a ninth pixel on the fly. For ordinary alphanumeric text (such as letters, numbers, and punctuation), this ninth pixel is rendered using the cell's background color. This behavior provides a built-in one-pixel margin between adjacent characters, preventing letters from colliding.

The Problem with Borders and Dividers

If every character received a blank ninth column, box-drawing characters and horizontal borders would fail. Characters designed to connect horizontally—such as single lines, double lines, and solid blocks—would leave a noticeable one-pixel vertical blank gap between adjacent cells, breaking the illusion of a solid continuous line or window frame.

Hardware Replication (Characters 0xC0 to 0xDF)

To solve this issue, IBM implemented a special hardware exception in the VGA display pipeline.

When generating the scanline for each character, the VGA controller inspects the character's code in the active code page (typically Code Page 437). For character codes in the hexadecimal range 0xC0 to 0xDF (decimal 192 through 223), the hardware alters its handling of the ninth pixel:

  • Standard characters (0x00–0xBF, 0xE0–0xFF): The 9th pixel is set to the background color.
  • Box-drawing characters (0xC0–0xDF): The hardware duplicates the state of the 8th pixel (the rightmost bit of the glyph) into the 9th pixel position.

If the eighth pixel of the glyph is lit (foreground color), the ninth pixel is also lit. If the eighth pixel is empty, the ninth remains empty. Because horizontal line glyphs are drawn all the way to the eighth pixel boundary in the ROM font, this duplication extends the line directly into the first pixel of the adjacent cell.

The Register Behind the Feature

This behavior is governed by the VGA Attribute Controller. Specifically, Bit 2 of the Attribute Controller Mode Control Register (Index 10h) is designated as the Enable Line Graphics Character Codes flag:

  • Bit 2 = 1 (Default in 9-dot text modes): Enables the automatic duplication of the eighth column to the ninth column for character codes 0xC0 through 0xDF.
  • Bit 2 = 0: Disables the duplication, forcing the ninth column to render as background color for all characters.

Vertical lines do not require special circuitry because the font glyphs already occupy the full 16 rows vertically, naturally touching the cells above and below them. Thanks to this column-duplication mechanism, DOS applications, setup utilities, and text-mode user interfaces could render seamless windows, tables, and borders on 720x400 VGA displays.
