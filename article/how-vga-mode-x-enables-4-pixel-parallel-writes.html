How VGA Mode X Enables 4-Pixel Parallel Writes

This article explores how IBM’s Video Graphics Array (VGA) architecture utilizes Mode X's planar memory arrangement to write four pixels concurrently. Mode X achieves this performance leap by "unchaining" VGA memory, mapping four separate 64 KB hardware planes to the same CPU memory address range. By configuring the VGA Sequencer's Map Mask register, a programmer can broadcast a single 8-bit color value to all four physical planes during a single memory cycle, effectively quadrupling write throughput for operations like screen clears and solid horizontal fills.

The Limits of Standard Mode 13h

Standard VGA 320x200 256-color graphics (Mode 13h) relies on a "chained" memory configuration. In this mode, the VGA hardware automatically interleaves writes across its four physical memory planes so the CPU sees memory as a flat, linear array of bytes. Each byte corresponds sequentially to a single pixel on screen. While this simplifies pixel addressing, it prevents the CPU from directly addressing more than 64 KB of video memory at a time and forces the CPU to write pixels one by one, requiring four separate bus cycles to update four contiguous pixels.

The Planar Architecture of Mode X

Mode X alters this layout by disabling Chain-4 mode via the VGA Sequencer and Graphics Controller registers. This turns the display memory into an unchained planar structure.

In Mode X:

  • The screen resolution remains 320x240 (or 320x200).
  • Video memory is divided across four parallel memory banks known as Plane 0, Plane 1, Plane 2, and Plane 3.
  • Pixels are distributed cyclically: Pixel 0 resides on Plane 0, Pixel 1 on Plane 1, Pixel 2 on Plane 2, and Pixel 3 on Plane 3.
  • Pixel 4 wraps back to Plane 0 at the next byte address, and the cycle repeats.

Because of this arrangement, four adjacent horizontal pixels share the exact same byte address in the CPU's memory map (located in segment 0xA000), distinguished only by the hardware plane in which they reside.

The VGA Map Mask Register

Writing to multiple planes simultaneously depends on the VGA Sequencer’s Map Mask Register (Address 0x3C5, Index 0x02). This 4-bit register acts as a write gate for the memory planes:

  • Bit 0 enables or disables writes to Plane 0 (Pixels 0, 4, 8...).
  • Bit 1 enables or disables writes to Plane 1 (Pixels 1, 5, 9...).
  • Bit 2 enables or disables writes to Plane 2 (Pixels 2, 6, 10...).
  • Bit 3 enables or disables writes to Plane 3 (Pixels 3, 7, 11...).

If a bit is set to 1, the corresponding plane accepts data written to the video memory address space. If set to 0, the plane ignores CPU write operations.

Executing the 4-Pixel Simultaneous Write

To write four pixels in a single instruction, the system performs two steps:

  1. Set the Write Mask: The program sends a command to the Map Mask register setting all four lower bits to 1 (binary 00001111 or 0x0F). This instructs the VGA hardware to open write paths to Planes 0, 1, 2, and 3 simultaneously.
  2. Execute the Write: The CPU executes a single byte write to an offset in video memory (for example, writing an 8-bit color index 0x2A to address 0xA000:0000).

The internal VGA bus duplicates the byte across all four hardware plane data paths. Because Planes 0 through 3 are all write-enabled at address 0x0000, the hardware updates:

  • Plane 0 (Pixel 0) with 0x2A
  • Plane 1 (Pixel 1) with 0x2A
  • Plane 2 (Pixel 2) with 0x2A
  • Plane 3 (Pixel 3) with 0x2A

In one memory access cycle, four distinct, consecutive pixels on the display receive the target color.

Performance and Utility

This parallel write capability reduces the CPU bus overhead needed to update the screen. For operations involving uniform colors—such as clearing the display, rendering solid user interface panels, or drawing flat-shaded polygons—Mode X achieves up to four times the write bandwidth of Mode 13h. Paired with 16-bit or 32-bit CPU string write instructions (REP STOSW or REP STOSD), developers can fill 8 or 16 pixels per loop iteration, overcoming one of the primary hardware bottlenecks of early PC graphics.
