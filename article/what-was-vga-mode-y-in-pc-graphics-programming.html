What Was VGA Mode Y in PC Graphics Programming?

VGA Mode Y was an undocumented, tweaked graphics mode for IBM-compatible PCs that provided an unchained 320x200 resolution with 256 colors, overcoming the memory and performance limitations of the standard BIOS Mode 13h. By disabling the VGA hardware's default memory chaining, Mode Y unlocked the full 256 KB of onboard video RAM to allow hardware page flipping, seamless scrolling, and faster parallel writes. The underlying technique of unchaining 320x200 was pioneered in the late 1980s by software developer John Bridges, while the specific moniker "Mode Y" was coined by the PC game development and demoscene community as a back-formation following Michael Abrash’s famous introduction of "Mode X."

The Limitations of Standard Mode 13h

When IBM introduced the Video Graphics Array (VGA) standard in 1987, the easiest way for developers to display 256 colors was BIOS Mode 13h. Mode 13h offered a resolution of 320x200 pixels where each byte in video memory directly corresponded to one pixel on the screen.

To achieve this simple linear memory model, IBM configured the hardware in "Chain-4" mode. The VGA's 256 KB of video memory was physically divided into four 64 KB memory banks called planes. In Chain-4 mode, hardware logic automatically directed consecutive bytes to consecutive planes (pixel 0 to plane 0, pixel 1 to plane 1, and so on).

While linear addressing made drawing routines simple, it had severe drawbacks:

  • Wasted Memory: The CPU could only access a single 64 KB memory window (0xA000:0000 to 0xA000:FFFF). Because a 320x200 screen consumes 64,000 bytes, virtually the entire accessible window was consumed by a single frame. The remaining 192 KB of VGA RAM sat idle and unreachable.
  • No Page Flipping: Because developers could not store multiple frames in video memory simultaneously, animation suffered from severe screen tearing unless rendering was artificially delayed to wait for the monitor’s vertical retrace.

How Mode Y Worked

Mode Y was created by taking standard Mode 13h and directly modifying VGA register settings to turn off Chain-4 addressing, switching the memory architecture into "planar" or "unchained" mode while keeping the 320x200 display timing intact.

In Mode Y, memory addresses no longer mapped linearly. Instead, four pixels shared the exact same memory address across the four distinct hardware planes:

  • Address 0 in Plane 0 controlled pixel (0, 0)
  • Address 0 in Plane 1 controlled pixel (1, 0)
  • Address 0 in Plane 2 controlled pixel (2, 0)
  • Address 0 in Plane 3 controlled pixel (3, 0)
  • Address 1 in Plane 0 controlled pixel (4, 0)

Because each plane only required 16,000 bytes to represent a full 320x200 image (\(320 \times 200 \div 4\)), a single display frame fit easily within the 64 KB plane limit. This unlocked critical capabilities:

  1. Hardware Page Flipping: Developers could fit up to four complete display pages into the 256 KB of video memory. Games could draw the next frame into a hidden page in the background and instantly swap the visible screen during the vertical blanking interval, eliminating screen flicker and tearing.
  2. Hardware-Accelerated Writes: The VGA hardware included internal latch registers and plane write-masks. A programmer could configure the hardware to write to all four planes simultaneously in a single CPU instruction, effectively painting four pixels at the cost of one memory write.
  3. Smooth Scrolling: Using the VGA's built-in start-address registers, games could scroll horizontally and vertically at the hardware level without redrawing the entire screen.

The Origin of the Name "Mode Y"

The planar 320x200 technique was first discovered and published in the late 1980s by John Bridges, an early PC graphics pioneer who worked on programs such as Paint Show and developed graphical tools for PC games. At the time, Bridges simply referred to it as an unchained or planar 320x200 VGA mode.

In July 1991, legendary programmer Michael Abrash published a landmark article in Dr. Dobb's Journal detailing an unchained 320x240 resolution. Abrash named his configuration "Mode X" to symbolize the unknown and to highlight its square 1:1 pixel aspect ratio on standard 4:3 CRT monitors.

Following the massive popularity of Abrash's article, developers who wanted the benefits of unchained VGA architecture without switching to the taller 240-line resolution returned to Bridges' unchained 320x200 configuration. The 320x200 mode retained a memory width stride of 320 bytes (80 bytes per plane), making memory offset calculations significantly faster and easier to optimize on 80286 and 80386 processors than the 240-line format.

As a humorous and logical nod to Abrash's "Mode X," programmers in the PC gaming community, BBS networks, and Usenet discussion groups (comp.sys.ibm.pc.programmer) began calling the unchained 320x200 setup "Mode Y." While John Bridges engineered the mechanics behind the mode, the "Mode Y" label was a community-coined term that completed the naming pair alongside Mode X during the golden era of DOS game programming.
