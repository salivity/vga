Why IBM VGA Switches Monochrome and Color Registers

When IBM introduced the Video Graphics Array (VGA) standard in 1987, it implemented hardware register switching between monochrome and color modes to maintain strict backward compatibility with legacy display hardware. Early PC software frequently bypassed the system BIOS to write directly to display hardware, relying on specific Input/Output (I/O) port addresses and video memory locations established by the Monochrome Display Adapter (MDA) and Color Graphics Adapter (CGA). By allowing the VGA chip to switch its register base addresses between monochrome and color assignments, IBM ensured that legacy applications continued to function without modification while still supporting advanced graphics and potential multi-monitor configurations.

Legacy I/O Port Division

In the original IBM PC architecture, the MDA and CGA cards were designed to coexist in the same machine without hardware conflicts. To achieve this, IBM allocated different memory spaces and I/O ports to each standard:

  • Monochrome (MDA): Mapped display RAM to memory address 0xB0000–0xB7FFF and mapped its Motorola 6845 Cathode Ray Tube Controller (CRTC) index and data registers to I/O ports 0x3B4 and 0x3B5. Its status register resided at 0x3BA.
  • Color (CGA): Mapped display RAM to memory address 0xB8000–0xBFFFF and mapped its CRTC index and data registers to I/O ports 0x3D4 and 0x3D5. Its status register resided at 0x3DA.

Because the 8088 processor was relatively slow, software developers of performance-critical applications—such as spreadsheets, word processors, and games—routinely bypassed slow BIOS calls. Instead, they hardcoded reads and writes directly to these specific I/O ports and memory addresses to manipulate text modes, cursor positions, and raster timings.

The Problem Facing VGA

When developing the VGA standard for the IBM PS/2 line, IBM engineers needed a single graphics subsystem capable of displaying both legacy text modes and advanced all-points-addressable color graphics. If VGA had permanently bound its CRTC registers to the color addresses (0x3D4/0x3D5), legacy software explicitly written for MDA hardware would fail, as those programs would attempt to communicate only through port 0x3B4. Conversely, hardcoding the registers to monochrome addresses would break software written for CGA and the Enhanced Graphics Adapter (EGA).

The Implementation: Dynamic Register Relocation

IBM resolved this conflict by introducing a hardware-level multiplexing mechanism controlled by the Miscellaneous Output Register (written at I/O port 0x3C2 and read at 0x3CC).

Bit 0 of this register, known as the I/O Address Select bit, directly controls the base address mapping for the VGA CRT Controller and the Input Status Register 1:

  • Bit 0 = 0 (Monochrome Mode): The CRTC index and data registers are mapped to 0x3B4 and 0x3B5, and Input Status Register 1 is mapped to 0x3BA. The frame buffer is restricted to the monochrome range starting at 0xB0000.
  • Bit 0 = 1 (Color Mode): The CRTC registers are mapped to 0x3D4 and 0x3D5, and Input Status Register 1 is mapped to 0x3DA. The frame buffer utilizes the color space starting at 0xB8000 (or 0xA0000 for graphics modes).

Whenever software requested a video mode change through the VGA BIOS (interrupt INT 10h), the BIOS programmed Bit 0 of the Miscellaneous Output Register according to whether the requested mode was monochrome (such as Mode 07h) or color (such as Modes 03h, 0Dh, or 12h).

Multi-Monitor Compatibility and Debugging

Beyond software compatibility, this register switching supported dual-adapter configurations. Because IBM VGA hardware could vacate the monochrome I/O ports and memory address space entirely when operating in color mode, users could install a secondary physical MDA or Hercules monochrome card alongside a VGA card.

Programmers widely used this setup for debugging: a debugger interface like Borland Turbo Debugger ran on the monochrome monitor connected to 0x3B4/0xB0000, while the primary application executed on the color VGA monitor connected to 0x3D4/0xB8000. If VGA had occupied both address ranges simultaneously, the resulting bus contention would have made hardware-level dual-screen debugging impossible.
