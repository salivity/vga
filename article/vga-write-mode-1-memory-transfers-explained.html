VGA Write Mode 1 Memory Transfers Explained

VGA Write Mode 1 is a specialized hardware-level data transfer mechanism designed to copy planar video memory directly to another memory location without CPU intervention. By utilizing the Video Graphics Array's four internal 8-bit latches, Write Mode 1 allows an application to read 32 bits of planar data (8 bits across 4 memory planes) and write that exact 32-bit slice to a new address using standard 8-bit read and write CPU instructions. This bypasses the standard processing pipeline, enabling exceptionally fast block-copy operations, such as scrolling and sprite blitting, on legacy hardware.

The Architecture of VGA Planar Memory

In standard 16-color graphics modes (such as Mode 12h, 640x480), VGA organizes video memory into four distinct memory planes (Planes 0, 1, 2, and 3). Each pixel's color is formed by taking one bit from each of the four planes at a given address, creating a 4-bit color index.

Because the standard PC system bus interacts with memory in byte-sized chunks, a standard CPU write cannot alter all four planes simultaneously with unique data in a single cycle. To facilitate operations across all four planes, the VGA Graphics Controller incorporates four internal 8-bit latches, providing a temporary 32-bit holding buffer directly on the graphics hardware.

Populating the Internal Latches

The transfer process in Write Mode 1 begins with a standard CPU read cycle:

  1. The CPU initiates a read operation from a specific video memory address.
  2. Regardless of which plane is designated for the CPU's read data (configured via the Read Map Select register), the VGA hardware automatically loads the data bytes from all four planes at that specific address into the four internal latches simultaneously.
  3. The latches now hold a full 32-bit snapshot of that memory coordinate (8 bits for Plane 0, 8 bits for Plane 1, 8 bits for Plane 2, and 8 bits for Plane 3).

The Write Mode 1 Transfer Mechanism

Write Mode 1 is configured by setting bits 0 and 1 of the Graphics Mode Register (Graphics Controller Index 05h) to 01b. Once activated, the write process functions as follows:

  1. CPU Destination Write: The CPU issues a memory write instruction (such as MOV) directed at a destination video memory address.
  2. Ignoring CPU Bus Data: Unlike Write Modes 0, 2, and 3, Write Mode 1 causes the VGA hardware to completely ignore whatever data byte is currently present on the CPU data bus. The CPU write cycle serves purely as an address strobe and timing trigger.
  3. Direct Latch-to-Memory Write: The VGA hardware immediately copies the byte stored in each of the four internal latches directly into its corresponding plane at the target memory address. Latch 0 writes to Plane 0, Latch 1 writes to Plane 1, Latch 2 writes to Plane 2, and Latch 3 writes to Plane 3.
  4. Bypassing the Arithmetic Logic Unit (ALU): The standard VGA data modification units—including the Data Rotate logic, the Bit Mask Register, and the Logical Operation functions (AND, OR, XOR)—are bypassed entirely during Write Mode 1.

Hardware Masking with the Sequencer Map Mask

While the CPU data and standard Graphics Controller masks are ignored, Write Mode 1 still respects the Sequencer's Map Mask Register (Index 02h). This register controls which memory planes are enabled for writing:

  • If a bit in the Map Mask Register is set to 1, the corresponding plane receives the byte from its latch.
  • If a bit is set to 0, the corresponding plane is protected from modification, leaving the existing memory at that plane unchanged.

This selective plane masking allows developers to perform block transfers on specific color components or planes while leaving other graphical layers untouched.

Efficiency and Performance

In normal operation, copying 32 bits across four planar memories would require the CPU to execute multiple read and write cycles, switching the active plane between operations via I/O port writes. Write Mode 1 reduces this entire sequence to two simple memory access cycles: one byte-read from the source address to fill the latches, followed by one byte-write to the destination address to commit the latches. This hardware-level latch transfer allowed early systems to achieve high-speed bit-block transfers (BitBLT) with minimal CPU cycle consumption.
