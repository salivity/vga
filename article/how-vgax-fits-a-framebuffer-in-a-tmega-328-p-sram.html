How VGAX Fits a Framebuffer in ATmega328P SRAM

The VGAX library allows an ATmega328P microcontroller—most commonly found on the Arduino Uno—to generate a live VGA video signal despite possessing only 2 KB (2,048 bytes) of SRAM. It accomplishes this feat through aggressive resolution scaling, low color-depth packing, scanline repetition, and cycle-exact AVR assembly routines. By reducing the virtual screen to 120x60 pixels at 2 bits per pixel, VGAX shrinks the entire framebuffer to 1,800 bytes, leaving the remaining 248 bytes for system stack and application state.

The Memory Math: 120x60 at 2 Bits Per Pixel

A standard 640x480 VGA display at 1 byte per pixel requires over 300 KB of RAM, an impossible requirement for the ATmega328P. VGAX overcomes this by setting the effective resolution to 120 horizontal pixels by 60 vertical pixels.

To maximize the use of every bit, VGAX uses a 2-bit color depth, offering four possible colors per pixel (typically black, red, green, and a combined color like yellow, determined by the pin assignments on the resistor DAC). Because each byte holds 8 bits, a single byte represents 4 horizontal pixels:

\[\frac{120 \text{ pixels}}{4 \text{ pixels per byte}} = 30 \text{ bytes per scanline}\]

\[30 \text{ bytes per scanline} \times 60 \text{ lines} = 1,800 \text{ bytes}\]

This allocation leaves 248 bytes of SRAM unoccupied, which is just enough memory to manage function calls, interrupt vectors, and user variables.

Scanline Repetition (Line Doubling)

Standard VGA monitors expect a 640x480 timing signal at a 60 Hz refresh rate with a horizontal sync frequency of approximately 31.47 kHz. An ATmega328P running at 16 MHz does not have enough processing power or memory to generate 480 unique lines of video data.

VGAX complies with standard VGA timing by repeating each stored pixel row across multiple monitor scanlines:

  • A standard 480-line active display area is divided into the 60 framebuffer lines.
  • Each line of the 1,800-byte buffer is read and transmitted sequentially across 8 consecutive horizontal scanlines (\(60 \times 8 = 480\)).
  • The microcontroller outputs pixels for one scanline, then re-reads the exact same 30 bytes from SRAM for the next seven scanlines before advancing to the next row in memory.

This approach creates tall, square pixels and satisfies the monitor's requirement for a standard 480p line count without requiring additional memory.

Bit Packing and Inline Assembly Transmission

Fetching and shifting 2-bit pixels in standard C/C++ introduces too much overhead to meet the rigid timing requirements of a VGA pixel clock. At 16 MHz, the MCU executes one instruction every 62.5 nanoseconds.

VGAX uses inline AVR assembly during the active display portion of each scanline:

  1. Direct Memory Addressing: Pointer registers load packed bytes sequentially from the static array allocated in SRAM.
  2. Shift and Mask: Dedicated assembly instructions unpack the two-bit values and map them directly to two digital output pins connected to the monitor's color lines.
  3. Deterministic Timing: Every clock cycle is accounted for, ensuring that horizontal sync (HSYNC) and vertical sync (VSYNC) pulses maintain standard intervals managed by the ATmega328P's internal hardware timers.

By combining an aggressive reduction in resolution, a packed 2-bit data structure, hardware-compatible line repeating, and cycle-counted assembly, VGAX successfully hosts an active video buffer entirely within the ATmega328P's 2 KB of SRAM.
