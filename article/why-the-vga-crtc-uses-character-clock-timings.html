Why the VGA CRTC Uses Character Clock Timings

The Video Graphics Array (VGA) standard, introduced by IBM in 1987, relies on a Cathode Ray Tube Controller (CRTC) to dictate display framing, synchronization, and memory addressing. Instead of counting individual pixels (dot clocks) for horizontal timings, the CRTC calculates these parameters using "character-clock" units, which typically represent 8 or 9 dot clocks. This design choice was driven by the silicon constraints of the late 1980s, the underlying memory architecture of the graphics subsystem, and backward compatibility with earlier display standards.

Historical Lineage and the Motorola 6845

The VGA architecture did not emerge in isolation; it was an evolution of the Monochrome Display Adapter (MDA), Color Graphics Adapter (CGA), and Enhanced Graphics Adapter (EGA). These older standards relied directly or conceptually on the Motorola 6845 CRTC.

The 6845 was designed primarily for character-based terminals and displays. It addressed memory and framed screens in terms of character cells rather than individual dots. Because VGA needed to maintain register-level and functional backward compatibility with EGA and CGA software, IBM preserved the core operational structure of the CRTC registers. Registers controlling Horizontal Total, Horizontal Display End, and Blanking intervals retained their character-oriented definitions.

Silicon Constraints and Clock Speeds

When VGA was introduced, standard logic operated at much lower switching speeds than modern hardware. A standard VGA resolution (such as 640x480 at 60 Hz) requires a pixel dot clock of approximately 25.175 MHz, while a 720x400 text mode requires 28.322 MHz.

In 1987, implementing wide counter circuits, comparators, and control logic that operated reliably at 25 MHz to 28 MHz inside a single-chip graphics controller was costly, consumed more power, and generated significant heat. By dividing the dot clock by 8 or 9 to derive a "character clock" (roughly 3.15 MHz), the internal timing engine of the CRTC could run at a fraction of the master dot clock rate. This drastically reduced the logic speed requirements for the horizontal timing chain.

Video Memory Architecture and Bus Widths

VGA video memory is organized into four parallel planes of DRAM accessed via an 8-bit or 16-bit system bus. Memory access cycles in the graphics subsystem are not performed on a dot-by-dot basis.

In text mode, the controller fetches a character code and an attribute byte every character clock, which the font generator expands into 8 or 9 visible dots. In graphic modes (such as Mode 12h, 640x480 16-color), memory reads fetch one byte per plane simultaneously. These four bytes represent 8 horizontal pixels across the four color planes. Because the display memory engine inherently loads and handles data in 8-pixel chunks, synchronizing horizontal CRTC parameters to this same 8-pixel or 9-pixel boundary simplified the address generation logic.

Functional Division: Sequencer vs. CRTC

The VGA hardware cleanly divides high-speed operations from low-speed control via two distinct components:

  • The Sequencer and Shift Registers: These components handle high-speed data flow. The Sequencer divides the master clock down to generate the character clock and controls the high-speed shift registers, which deserialize memory data into the high-frequency stream of individual dots fed to the Digital-to-Analog Converter (DAC).
  • The CRTC: This block generates the complex framing signals—Horizontal Sync, Vertical Sync, and Blanking intervals—and increments the display memory address. By offloading dot-rate serialization to dedicated shift registers, the CRTC only needs to track timing at the character-clock rate.

Handling 8-Dot and 9-Dot Modes

VGA accommodates both 8-pixel-wide graphics modes (such as 320x200 or 640x480) and 9-pixel-wide text modes (such as 720x400). The Sequencer includes a Clocking Mode Register that switches the character clock divisor between 8 and 9 dot clocks.

By measuring horizontal parameters in character clocks, the overall frame timing and monitor sync pulses remain fundamentally identical between 640-pixel graphics and 720-pixel text modes. The CRTC executes the exact same number of horizontal character clocks per line, while the Sequencer dynamically handles the underlying dot division.
