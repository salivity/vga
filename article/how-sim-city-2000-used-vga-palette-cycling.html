How SimCity 2000 Used VGA Palette Cycling

In the early 1990s, hardware limitations required game developers to use innovative rendering tricks to produce dynamic visuals without exhausting system resources. This article explains how Maxis implemented Video Graphics Array (VGA) palette rotation—also known as palette cycling—in SimCity 2000 to animate environmental elements like flowing water and hazards, shifting color look-up tables rather than redrawing screen pixels to achieve smooth, real-time animation.

The Mechanics of 256-Color Indexed VGA

Standard 256-color VGA modes (such as Mode 13h) allocate 8 bits of memory per pixel. Instead of storing direct red, green, and blue (RGB) color values for every pixel on the screen, each pixel stores an index number ranging from 0 to 255.

These index numbers point to a color look-up table (CLUT) housed in the graphics hardware's Digital-to-Analog Converter (DAC). The DAC maps each index to an 18-bit RGB color (6 bits per channel). When the monitor scans across the screen, it reads the pixel's index number and outputs the RGB value currently assigned to that index in the palette table.

How Palette Rotation Works

Palette rotation exploits the disconnect between pixel memory and the color table. Under standard rendering, animating a scene requires the CPU to write new pixel values into Video RAM (VRAM) for every frame—a process limited by the slow bus bandwidth of early PC architectures like ISA.

With palette rotation, the pixel data in VRAM never changes. Instead, the game shifts the RGB values assigned to a specific subset of palette indexes:

  1. A block of consecutive palette indexes is reserved for animation (for example, indexes 240 through 247).
  2. The RGB value of index 247 moves to a temporary buffer.
  3. Indexes 240 through 246 shift their RGB definitions up by one slot.
  4. The buffered color is assigned to index 240.
  5. On the next display refresh, every pixel on the screen referencing those indexes automatically displays the shifted color.

Environmental Effects in SimCity 2000

SimCity 2000 features dense isometric views containing thousands of individual tiles. Re-rendering large bodies of water or environmental disruptions on a 386 or 486 processor would have caused severe framerate drops. Maxis used palette cycling to power several key environmental effects:

  • Flowing Water and Waterfalls: Maxis painted water tiles using a sequential set of blue, cyan, and white indexed colors arranged in directional gradients. When the game rotated the RGB values across these indexes, the water tiles appeared to ripple, crest, and flow. Waterfalls appeared to cascade rapidly by cycling high-contrast blues and whites down the slope.
  • Shorelines and Waves: Coastlines featured gradients mapped to the cycling color set, giving the visual illusion of waves perpetually breaking against the shore without updating any shoreline tile data.
  • Lava and Volcanic Disasters: When a volcano disaster occurs, the molten rock utilizes palette rotation across a range of reds, oranges, and yellows. The cycling colors made the lava appear to bubble, churn, and radiate heat.
  • Emergency and Industrial Indicators: Nuclear power plants, emergency vehicles, and specific industrial tiles used targeted cycling registers to produce flashing indicator lights and glowing hazards without dedicated sprite frames.

Performance and Visual Benefits

Because palette rotation operates entirely within the VGA DAC registers, the CPU only needs to update a few dozen bytes per frame during the vertical blank interval (VBLANK). This technique completely bypassed the system bus bottleneck, prevented visual tearing, and allowed SimCity 2000 to maintain vibrant, moving landscapes across massive city grids on modest hardware.
