CPU and VGA CRTC Memory Contention Explained

This article examines the memory access conflict that occurs when a system's central processing unit (CPU) and a Video Graphics Array (VGA) Cathode Ray Tube Controller (CRTC) attempt to read or write video memory simultaneously. It explores the hardware constraints of single-ported video RAM, the performance and visual implications of memory bus contention, and the mechanisms engineers implemented to resolve these simultaneous access requests.

The Root Cause: Single-Ported Memory

Early PC graphics subsystems, including standard VGA adapters, relied primarily on conventional dynamic RAM (DRAM) rather than expensive dual-ported video RAM (VRAM). Single-ported DRAM possesses only one set of address and data buses. Consequently, it can only service one memory access cycle at any given fraction of time—it cannot physically read or write data for two independent controllers at the exact same instant.

A fundamental conflict arises because the CPU and the CRTC have competing, asynchronous demands on this shared pool of memory:

  • The CRTC's Demands: The CRTC is bound to strict, real-time hardware timings. To output an image, it must sequentially and continuously fetch pixel data from memory to send to the palette digital-to-analog converter (RAMDAC). If the CRTC misses a cycle, the video raster beam continues to sweep across the monitor without the necessary pixel data, leading to display disruption.
  • The CPU's Demands: The CPU requires random read and write access to video memory to update the screen state, render primitives, move sprites, or manipulate framebuffers.

The Manifestation of the Conflict

When both the CPU and the CRTC attempt to access video memory on the same clock cycle, bus contention occurs. In earlier hardware architectures like the Color Graphics Adapter (CGA), uncoordinated simultaneous access forced the memory bus to service the CPU during active raster sweeps, preventing the display circuitry from receiving valid character or pixel data. This manifested visually as "snow"—sparkling, random static across the display.

In the VGA standard, the hardware architecture avoided visual snow by implementing strict bus arbitration, but this shift moved the penalty from the display output to CPU performance.

Arbitration and Wait States

To prevent display artifacts, the VGA memory controller generally gives the CRTC priority during active display cycles. When the CPU attempts to read or write to video memory while the CRTC is actively reading raster data:

  1. Assertion of Wait States: The VGA memory controller forces the host bus (typically the ISA bus) to delay the CPU by de-asserting the I/O CH RDY (I/O Channel Ready) signal.
  2. CPU Stalling: The CPU is placed into a hardware wait state, pausing its execution pipeline until the video memory controller finishes servicing the CRTC's immediate request.
  3. Bandwidth Throttling: As a result, reading from or writing to VGA memory during an active display period suffered from extreme latency compared to standard system RAM, creating a massive processing bottleneck for graphics-heavy applications.

Architectural Solutions

Engineers employed several hardware and software strategies to mitigate the simultaneous access conflict:

  • Time-Division Multiplexing (Interleaving): The VGA architecture interleaves access cycles within the pixel clock domain. The memory controller rapidly alternates between servicing the display pipeline and servicing CPU requests within specific clock phases.
  • FIFO Line Buffers: VGA implementations incorporate small First-In, First-Out (FIFO) buffers. The CRTC burst-reads pixel data into the buffer, allowing the display pipeline to run off the buffer for several cycles while freeing the memory bus entirely for the CPU.
  • Blanking Interval Access: Programmers minimized contention by synchronizing memory access with the CRTC's vertical blanking interval (VBLANK) and horizontal blanking interval (HBLANK). During these intervals, the electron beam is turned off while repositioning, meaning the CRTC requires zero memory bandwidth, allowing the CPU full, unhindered access to VRAM.
