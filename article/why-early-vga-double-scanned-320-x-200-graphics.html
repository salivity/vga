Why Early VGA Double Scanned 320x200 Graphics

Early Video Graphics Array (VGA) hardware utilized scan line doubling for 320x200 display modes primarily to maintain electrical and timing compatibility with fixed-frequency analog monitors. When IBM introduced the VGA standard in 1987, it standardized on a horizontal scan frequency of 31.468 kHz at a 70 Hz refresh rate, which required around 400 active lines per frame. By reading each line of display memory twice, the VGA controller produced 400 physical scan lines from a 200-line framebuffer, allowing legacy low-resolution graphics to display correctly without requiring expensive multi-frequency monitors.

The Problem of Monitor Timings

Earlier display standards, such as IBM's Color Graphics Adapter (CGA), operated at a horizontal scan rate of approximately 15.75 kHz and a vertical refresh rate of 60 Hz. This timing allowed the electron gun of a CRT to trace 262 total lines per frame, with 200 lines actively dedicated to visible picture data.

VGA drastically upgraded the display experience by doubling the horizontal scan frequency to roughly 31.5 kHz. At a 70 Hz vertical refresh rate, the math dictates the required line count:

\[\frac{31,468\text{ Hz}}{70\text{ Hz}} \approx 449.5\text{ total lines per frame}\]

Subtracting the lines dedicated to vertical blanking, overscan, and sync intervals left room for exactly 400 active visible scan lines. If VGA hardware had attempted to output only 200 lines without modification, the horizontal frequency would have had to drop back to 15.75 kHz. Fixed-frequency VGA monitors were not engineered to sync to such low frequencies and doing so would result in an unsynchronized picture or even hardware damage to the display.

Hardware-Level Double Scanning

To solve this mismatch while preserving backwards compatibility with legacy 320x200 formats—such as the widely popular VGA Mode 13h—IBM engineered a feature into the VGA Cathode Ray Tube Controller (CRTC) called double scanning.

In hardware, the CRTC contains a Maximum Scan Line register. In standard 400-line or 480-line modes, this register is set so the controller advances to the next row of display memory after every horizontal scan line. When operating in a 200-line mode, the hardware sets this register to repeat each memory row.

As the electron gun sweeps horizontally across the CRT:

  1. It draws the first line of pixels from row zero of video RAM.
  2. During the horizontal blanking interval, the beam resets to the left side of the screen, but the memory pointer does not advance.
  3. The electron gun sweeps again, drawing the identical pixel data from row zero a second time.
  4. The memory address advances to row one, repeating the cycle for all 200 logical rows.

Memory and Performance Benefits

Beyond monitor compatibility, double scanning solved a critical computing constraint of the late 1980s: memory bandwidth and processor performance.

A 320x200 mode using 256 colors requires 64,000 bytes of video memory—just under the standard 64 KB segment limit of real-mode x86 processors. This allowed developers to address the entire screen using a single base pointer without complex segment swapping or bank switching.

If the hardware had required a native 320x400 or 640x400 framebuffer to satisfy the 400-line requirement, video memory requirements would have doubled to 128 KB. Contemporary CPUs, such as the 80286 and early 80386 systems, would have faced severe performance bottlenecks simply copying double the data to the video card. Hardware double scanning delivered the required 31.5 kHz signal without placing any additional processing or memory burden on the host computer.
