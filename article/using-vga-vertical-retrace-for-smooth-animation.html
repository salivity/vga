Using VGA Vertical Retrace for Smooth Animation

Synchronizing software rendering with the display hardware is fundamental to achieving fluid visual motion on legacy systems. In Video Graphics Array (VGA) programming, software developers rely on the vertical retrace interrupt—also known as the Vertical Blanking Interval (VBLANK)—to update frame data and display pointers without interrupting active screen rendering. By aligning memory updates with this brief hardware pause, developers eliminate visual artifacts like screen tearing, stabilize frame rates, and execute flicker-free palette animations.

The Vertical Retrace Mechanism

Cathode Ray Tube (CRT) monitors display images by sweeping an electron beam horizontally across the screen, line by line, from top to bottom. Once the beam reaches the bottom-right corner, it must be turned off (blanked) and repositioned back to the top-left corner to begin drawing the next frame. This reset period is the vertical retrace.

During active display time, reading and writing directly to the VGA video memory (VRAM) while the beam reads from the same memory causes "tearing"—a visual artifact where portions of two different frames appear simultaneously on screen. The vertical retrace provides a brief window where the electron beam is inactive, allowing developers to modify video hardware registers or alter video memory safely.

Hardware Interrupts vs. Register Polling

Developers primarily interface with vertical retrace using two techniques: hardware interrupts or register polling.

1. Polling the Input Status Register

The most common approach in PC game development involves reading bit 3 of the VGA Input Status #1 Register (port 0x3DA on color displays). When this bit is set to 1, the hardware is in the vertical retrace period.

Developers implement a tight loop that first waits for any ongoing retrace to finish, and then waits for the new retrace to begin:

// Wait until any existing retrace finishes
while ((inportb(0x3DA) & 0x08) != 0);

// Wait until the new vertical retrace begins
while ((inportb(0x3DA) & 0x08) == 0);

While this method wastes CPU cycles, it is straightforward and guaranteed to work across virtually all PC-compatible clones.

2. Using the Vertical Retrace Interrupt (IRQ 9 / IRQ 2)

VGA hardware can also trigger an interrupt at the start of the vertical retrace (typically routed via IRQ 2/IRQ 9 on IBM PC/AT architecture). To use this, developers program the VGA's Cathode Ray Tube Controller (CRTC) registers—specifically clearing the interrupt flip-flop and enabling the vertical interrupt enable bit in the Vertical Retrace End Register (Index 0x11).

Using an interrupt service routine (ISR) frees the CPU from busy-waiting. When the interrupt fires, the ISR executes critical display-switching logic immediately, leaving the remaining frame time for calculations, physics, and off-screen rendering.

Techniques Enabled by Vertical Retrace

Developers use the vertical retrace window to implement several visual techniques:

Page Flipping (Hardware Double Buffering)

Instead of copying full frame data to VRAM during the retrace—which often exceeds the duration of the retrace window—developers configure the VGA hardware with multiple display pages.

  1. One buffer is displayed on the monitor while the application draws to the secondary, hidden buffer.
  2. When drawing finishes, the program waits for the vertical retrace.
  3. During the retrace, the program updates the CRTC Start Address registers (Index 0x0C and 0x0D) to point to the memory location of the newly drawn frame.
  4. When the beam begins scanning from the top, it immediately displays the new buffer without any tearing.

Palette Modifications and Copper-Style Effects

In standard 256-color modes (such as Mode 13h), the Digital-to-Analog Converter (DAC) contains the color lookup table. Modifying the DAC during active scanning causes visible visual noise or "snow." By updating the palette registers (0x3C8 and 0x3C9) during vertical retrace, developers achieve smooth color cycling, fading effects, or screen-wide lighting changes with no visual distortion.

Fixed-Rate Frame Synchronization

Because vertical retrace occurs at deterministic hardware intervals (typically 60 Hz or 70 Hz depending on the resolution), synchronizing game loops to the retrace provides an automatic, hardware-level clock. This eliminates the need for complex software timers to normalize game speed across different processor architectures.
