How VGA Bank Switching Bypassed the 64 KB Barrier

In early x86 PC architectures running in real mode, the processor was inherently constrained by a 16-bit addressing scheme that limited accessible memory segments to 64 KB. As graphics demands grew, standard Video Graphics Array (VGA) adapters shipped with 256 KB of Video RAM (VRAM), and Super VGA (SVGA) cards expanded far beyond that. To allow software to access these large framebuffers without abandoning real-mode compatibility, hardware designers implemented bank switching—also known as memory windowing—which dynamically mapped distinct physical portions of VRAM into a dedicated 64 KB aperture in the system's address space.

In real-mode x86 architecture, memory addresses are computed using a 16-bit segment and a 16-bit offset. Because a 16-bit register can only index values from 0x0000 to 0xFFFF, a single segment cannot exceed 64 KB without changing segment registers, and the architecture reserved only a limited window in the Upper Memory Area (typically segment 0xA000, covering 0xA0000 to 0xAFFFF) for graphical display buffers. Higher-resolution modes easily exceeded this allocation. For example, a 640x480 display with 256 colors requires over 300 KB for a single frame, making it impossible to address the entire framebuffer simultaneously within a single 64 KB address space.

Standard VGA hardware addressed this through a combination of planar memory and bit-plane multiplexing. The 256 KB of onboard memory was split into four parallel 64 KB memory planes (Planes 0 through 3). The CPU mapped all four planes to the exact same 64 KB memory window at 0xA0000. By configuring internal VGA registers via I/O ports—specifically the Sequencer and the Graphics Controller—software could select which plane to read from or write to, or use hardware latches to modify data across all four planes in a single memory operation. This internal multiplexing effectively fit 256 KB of data into a 64 KB footprint, allowing high-resolution 16-color modes to operate within real-mode limitations.

As SVGA cards emerged with flat, 8-bit-per-pixel and true-color modes, planar addressing became insufficient, requiring true bank switching. SVGA controllers divided the multi-megabyte VRAM into sequential 64 KB chunks (banks or pages). The graphics card hardware acted as an intermediary: whenever the CPU issued a read or write to an address between 0xA0000 and 0xAFFFF, the graphics card added an offset to the physical memory address based on a value stored in an onboard banking register.

To draw an entire screen using bank switching, a programmer used the following process:

  1. Write graphical data to addresses 0xA000:0000 through 0xA000:FFFF, populating the first 64 KB of the screen.
  2. Send a command to the graphics card's I/O port (or invoke a VESA BIOS Extension routine, such as INT 10h, AX=4F05h) to increment the bank index.
  3. The graphics hardware shifted its internal pointer, making the next 64 KB of physical VRAM visible at 0xA0000.
  4. Resume writing from offset 0x0000 using the exact same CPU addresses, which now modified the next slice of the physical framebuffer.

This mechanism introduced a performance penalty and added complexity to rendering engines, which had to handle graphical primitives (such as lines or bitmaps) that crossed over a 64 KB boundary. Some hardware mitigated this by providing two independent windows—one for reading and one for writing—or separate banks mapped to different ranges within the 0xA0000–0xBFFFF region. Despite the overhead of frequently updating bank registers, bank switching allowed legacy DOS applications to utilize large framebuffers decades before protected-mode flat memory models became standard.
