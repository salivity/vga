VGA Palette Snow Artifact Explained

Modifying Video Graphics Array (VGA) palette registers outside the retrace blanking interval produces a distinct visual glitch commonly referred to as "snow" or "palette snow." This artifact manifests as flickering speckles, noise, or short horizontal streaks of incorrect colors scattered across the active display area. This article examines the hardware mechanics behind VGA palette snow, why memory access collisions generate this noise, and the programming techniques historically used to prevent it.

The Mechanics Behind Palette Snow

In classic VGA hardware, the Video Digital-to-Analog Converter (RAMDAC) holds the color lookup table (CLUT) responsible for mapping pixel attribute values to RGB color outputs. During the active display period, the electron beam scans across the screen line by line, requiring the RAMDAC to continuously and rapidly read palette memory to generate the analog color signals in real time.

Original VGA adapters and their RAMDACs generally lacked multi-port memory for the palette registers. Consequently, if the CPU attempts to write to the palette registers (via I/O ports 0x3C8 and 0x3C9) while the RAMDAC is actively reading them to draw pixels, a bus contention or access collision occurs. During this brief conflict, the RAMDAC receives corrupted or invalid data for the current pixel cycle, resulting in an erroneous burst of color or brightness sent directly to the monitor. Visually, these microsecond errors appear as a scattering of bright or dark dots resembling television static or "snow."

Safe Update Windows: Retrace Intervals

To update color palettes without corrupting the active image, changes must be synchronized with the CRT electron beam's inactive periods:

  • Horizontal Blanking Interval (HBI): The brief window when the electron beam turns off and moves from the right edge of the screen back to the left edge to start the next scanline. Because HBI periods are extremely short, only a few palette registers can be safely written per line.
  • Vertical Blanking Interval (VBI): The longer period when the beam finishes drawing the bottom of the screen and travels back up to the top left corner. This window provides sufficient time for the CPU to update multiple palette entries—or the entire 256-color palette—without colliding with display generation.

How Developers Prevented the Glitch

To avoid palette snow, DOS and early PC game programmers synchronized palette transfers with the hardware's timing signals:

  1. Polling the Input Status Register: Developers polled VGA Input Status Register 1 (located at I/O port 0x3DA). Bit 3 of this register indicates whether a vertical retrace is currently active.
  2. Wait Loops: Code was structured to wait until any in-progress retrace finished, then wait for the start of the next vertical retrace.
  3. Burst Writing: Once the start of the VBI was detected, the CPU rapidly transferred updated color data from a system memory buffer to the VGA DAC registers before the active display cycle resumed.
