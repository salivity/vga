VGA Mode X: Smooth 2D Multi-Directional Scrolling

Mode X was an undocumented video mode for standard VGA hardware popularized by Michael Abrash in the early 1990s that revolutionized 2D PC gaming. By configuring the VGA controller into an unchained planar configuration at a resolution of 320x240, Mode X gave developers access to the full 256 KB of video RAM, hardware-level page flipping, fast planar data transfers, and hardware scrolling registers. These architectural capabilities eliminated the severe performance bottlenecks of standard Mode 13h, enabling silky-smooth, tear-free multi-directional scrolling in classic DOS games.

Access to Full Video Memory and Multiple Display Pages

Standard VGA Mode 13h (320x200, 256 colors) used a "chained" memory model that mapped adjacent pixels to consecutive memory addresses. While easy to program, it artificially limited usable video RAM to a single 64 KB aperture. Because a single 320x200 screen consumed 64,000 bytes, developers could not fit a second display buffer in video memory. Double buffering had to be done in system RAM and copied over the slow ISA bus, causing visible tearing or low frame rates.

Mode X switched the VGA controller to "unchained" planar mode. In this mode, every four horizontal pixels were distributed across four separate 64 KB memory planes at the same memory address. This unlocked the entire 256 KB of onboard VGA RAM. At a resolution of 320x240, a single frame required only 76,800 bytes (19,200 bytes per plane). This left enough room for up to three full display pages in VRAM simultaneously, allowing true hardware page flipping without consuming ISA bus bandwidth for full-screen copies.

Hardware-Accelerated Viewport Shifting

In chained modes, moving a camera view typically required redrawing or shifting the entire screen memory. Mode X eliminated this requirement by exposing the VGA's internal CRT Controller (CRTC) registers:

  • CRTC Start Address Register: Developers could program the Start Address High and Start Address Low registers to point the VGA display generator to any arbitrary byte offset in video RAM. Changing these registers instantly shifted the displayed screen horizontally and vertically on the next vertical blanking interval.
  • Vertical Scrolling: Incrementing or decrementing the start address by the width of a display row (80 bytes per plane) shifted the display up or down by one scanline instantaneously.
  • Coarse Horizontal Scrolling: Adjusting the start address by one byte shifted the display horizontally by four pixels (since one byte spans four horizontal pixels across the four planes).

Sub-Byte Pixel Panning

Because byte-level adjustments in planar mode move the screen in four-pixel increments, coarse scrolling alone resulted in choppy motion. Mode X solved this by utilizing the VGA's Horizontal Pel Panning register (part of the Attribute Controller).

This register allowed fine-tuning of the horizontal display start point on a sub-byte level, shifting the display by 0, 1, 2, or 3 individual pixels. By pairing coarse adjustments via the CRTC Start Address register with fine adjustments via the Pel Panning register, developers achieved seamless, per-pixel horizontal and vertical scrolling in any direction simultaneously.

Efficient Boundary Tile Updating

Smooth scrolling requires dynamically rendering new map data just outside the visible viewport before it scrolls into view. Mode X made this efficient through a combination of off-screen VRAM buffering and VGA write modes:

  1. Virtual Canvases: Because Mode X provided 256 KB of VRAM, developers could define virtual screen spaces wider and taller than the physical display (for example, a 400x300 virtual canvas). The hardware viewport could freely scroll within this area.
  2. Off-Screen Edge Drawing: As the camera moved, the engine only had to render new 8x8 or 16x16 tiles along the leading edge of the scroll direction into off-screen memory, rather than redrawing the whole scene.
  3. Hardware Latches and Planar Writes: In planar mode, writing a single byte could update up to four pixels at once using the VGA's Map Mask register. Additionally, developers could use the VGA's internal 32-bit latch registers to copy data between VRAM locations with single-byte CPU instructions, drastically accelerating tile blitting and edge updates.

Square Pixels for Uniform Geometry

Mode 13h operated at 320x200, which stretched pixels vertically on a standard 4:3 monitor (a non-square 1:1.2 aspect ratio). Mode X operated at 320x240, which matched the standard 4:3 display aspect ratio exactly. This square pixel aspect ratio ensured that diagonal camera movements, physics calculations, and circular rotations traversed identical horizontal and vertical distances in screen space, simplifying collision logic and producing visually uniform multi-directional motion.
