Why VGA Memory Window at 0xA0000 Was Limited to 64 KB

The Video Graphics Array (VGA) memory window at physical address 0xA0000 was constrained to 64 KB due to a combination of Intel’s 16-bit real-mode segmentation architecture, the original IBM PC memory map, and backward compatibility with earlier display standards. Although standard VGA cards featured 256 KB of video RAM, the system could only expose 64 KB at a time to the CPU between addresses 0xA0000 and 0xAFFFF. This design choice enabled seamless execution on legacy 8086/8088 systems and avoided collisions with existing monochrome and color text video buffers.

The IBM PC Memory Map and the 640 KB Barrier

When IBM designed the original 5150 PC around the Intel 8088 microprocessor, the CPU could address a total of 1 MB (1,048,576 bytes) of physical memory. IBM split this 1 MB address space into two primary sections:

  • 0x00000 to 0x9FFFF (640 KB): Conventional memory reserved for the operating system (DOS) and user programs.
  • 0xA0000 to 0xFFFFF (384 KB): The Upper Memory Area (UMA), reserved for hardware peripherals, system ROMs, and video display adapters.

Within the Upper Memory Area, IBM allocated a 128 KB block spanning 0xA0000 to 0xBFFFF specifically for video memory.

Preventing Collisions with Legacy Video Hardware

The 128 KB video block was deliberately subdivided among competing display standards:

  • 0xA0000 – 0xAFFFF (64 KB): Reserved for enhanced graphics adapters (originally EGA, then VGA).
  • 0xB0000 – 0xB7FFF (32 KB): Reserved for the Monochrome Display Adapter (MDA).
  • 0xB8000 – 0xBFFFF (32 KB): Reserved for the Color Graphics Adapter (CGA).

By confining the VGA graphics window strictly to 0xA0000 through 0xAFFFF, IBM ensured that VGA-equipped machines could run secondary monochrome monitors or legacy software without causing hardware address conflicts. Mapping beyond 0xAFFFF would have immediately overlapped with MDA and CGA memory buffers, breaking system compatibility.

Alignment with Intel x86 Real-Mode Segmentation

The 64 KB size was also dictated by the native segmented architecture of the Intel 8086 and 8088 processors. In real mode, memory addressing relies on a 16-bit segment register paired with a 16-bit offset. Because a 16-bit offset can only address values from 0x0000 to 0xFFFF, a single segment spans exactly 64 KB (\(2^{16}\) bytes).

By setting the segment register (such as ES or DS) to 0xA000, software could access the entire video aperture simply by manipulating the 16-bit offset register without recalculating or changing segment registers. This simplified software development and maximized drawing performance on CPU architectures where modifying segment registers was computationally expensive.

Accessing 256 KB of Video Memory Through a 64 KB Window

Because standard VGA hardware included 256 KB of physical VRAM—four times the size of the 64 KB window—VGA hardware did not map memory in a linear 1:1 format. Instead, it organized the 256 KB of memory into four parallel 64 KB "planes" (Plane 0 through Plane 3).

Programs accessed these planes simultaneously across the same 0xA0000–0xAFFFF address space using internal VGA controller registers:

  • Planar Modes (e.g., Mode 12h, 640x480, 16 colors): Each byte written by the CPU could modify up to four planes at once through hardware write modes, latches, and bit-mask registers.
  • Linear Modes (e.g., Mode 13h, 320x200, 256 colors): The hardware interleaved pixels across the planes internally so that the CPU perceived a continuous 64,000-byte buffer that fit comfortably within the 64 KB aperture.

Later Super VGA (SVGA) standards introduced high-resolution modes requiring far more than 64 KB of linear space. Because the legacy memory map could not be altered without breaking compatibility, SVGA manufacturers retained the 64 KB window at 0xA0000 and introduced "bank switching" (paging) registers to swap different 64 KB slices of physical video RAM in and out of that single address block.
