How to Program VGA Raster Bars

This article explores the classic raster bar visual effect and provides a direct technical guide to implementing it on PC Video Graphics Array (VGA) hardware. You will learn what raster bars are, how they exploit CRT display timing, and how to program them directly by polling VGA I/O ports and modifying the hardware color palette on a scanline-by-scanline basis without redrawing the frame buffer.

What Is a Raster Bar Effect?

A raster bar (often called a raster beam or copper bar) is a classic computer graphics effect popularized in the 1980s and 1990s demoscene on platforms like the Commodore Amiga, Atari ST, and IBM PC. Visually, it consists of horizontal, shaded color bands that bounce, wave, or stretch smoothly across the screen.

Unlike traditional 2D computer graphics, raster bars are generally not drawn into the video frame buffer memory. Instead, they are generated dynamically by altering hardware color registers in real time as the monitor's electron beam scans across the screen line by line. By changing the RGB value of a specific palette index (typically color index 0, the background) right before a scanline begins drawing, the entire horizontal line takes on that new color with zero pixel-drawing overhead.

VGA Timing and the Video Beam

To display an image, an analog CRT monitor uses an electron beam that sweeps left-to-right to draw horizontal scanlines, and top-to-bottom to draw the full frame. VGA hardware exposes specific hardware status flags that indicate the position of this sweep:

  1. Horizontal Blank (HBlank): The brief period when the electron gun finishes a line, turns off, and returns to the left edge of the screen to begin the next line.
  2. Vertical Blank (VBlank): The longer period when the gun reaches the bottom of the screen, turns off, and resets back to the top left to start a new frame.

On a PC VGA adapter, the CPU reads the state of these blanking intervals via Input Status Register 1, located at I/O port address 0x03DA.

  • Bit 3 (0x08): Vertical Retrace (1 = VBlank active, 0 = display area active).
  • Bit 0 (0x01): Display Disable / Horizontal Retrace (1 = beam is blanked/retrace, 0 = beam is actively drawing pixels).

The VGA Color Palette (DAC) Registers

VGA color graphics (such as standard Mode 13h: 320x200 at 256 colors) use a palette lookup table managed by the Digital-to-Analog Converter (DAC). The DAC allows 256 colors to be selected from an 18-bit color space (6 bits each for Red, Green, and Blue, ranging from 0 to 63).

The palette is programmed using two primary ports:

  • Port 0x03C8 (PEL Address Write Mode): Specifies which palette index (0–255) to alter.
  • Port 0x03C9 (PEL Data Register): Accepts three sequential byte writes representing Red, Green, and Blue values (0 to 63 each).

Step-by-Step Programming Process

To generate a stable raster bar on a VGA card in standard C and x86 Assembly, execute the following loop every frame:

1. Disable Interrupts

Because the effect relies on microsecond-accurate hardware timing, background software interrupts (such as the system timer or keyboard poll) will cause visible tearing, jitter, or shaking. Disable interrupts before the timing loop begins using the CLI assembly instruction, and re-enable them after the frame completes using STI.

2. Synchronize to the Vertical Retrace

Wait for the start of a new frame to prevent tearing and keep the bars anchored to the same vertical position:

// Wait for any existing VBlank to end
while (inportb(0x03DA) & 0x08);

// Wait for the new VBlank to begin
while (!(inportb(0x03DA) & 0x08));

3. Count Scanlines to the Bar Position

After VBlank finishes, determine where on the screen the bar should start. You can count horizontal retrace cycles by repeatedly waiting for Bit 0 of 0x03DA to toggle.

void wait_hblank() {
    // Wait until the beam is drawing
    while (inportb(0x03DA) & 0x01);
    // Wait until the beam enters HBlank
    while (!(inportb(0x03DA) & 0x01));
}

By calling this function in a loop \(N\) times, you position the execution at scanline \(N\).

4. Update the Palette During HBlank

A gradient table containing predefined RGB values for each line of the bar is applied consecutively. To prevent visual artifacts known as "snow" or mid-line palette artifacts, write to the DAC registers only during the HBlank window:

// Array containing the color gradient (Red component example)
unsigned char bar_gradient[16] = {
    1, 4, 8, 15, 23, 32, 45, 63, 63, 45, 32, 23, 15, 8, 4, 1
};

// Set DAC to write Color 0 (background)
outportb(0x03C8, 0);

for (int i = 0; i < 16; i++) {
    wait_hblank();
    
    // Write RGB to Color 0
    outportb(0x03C9, bar_gradient[i]); // Red
    outportb(0x03C9, 0);               // Green
    outportb(0x03C9, 0);               // Blue
}

// Reset background color to black after the bar finishes
wait_hblank();
outportb(0x03C8, 0);
outportb(0x03C9, 0);
outportb(0x03C9, 0);
outportb(0x03C9, 0);

5. Animate Movement

To move the raster bar up and down the screen across frames, adjust the starting scanline offset over time using a precomputed sine lookup table. By layering multiple offsets and blending palettes across separate tables, developers create the illusion of multiple independently floating, translucent bars.
