How Demogroups Hacked VGA Beyond Its Limits

During the late 1980s and early 1990s, European demoscene groups turned the IBM PC from an office machine into a high-performance multimedia platform by bypassing standard BIOS calls and directly reprogramming the Video Graphics Array (VGA) hardware. By exploiting undocumented registers, altering CRT controller timings, and reconfiguring planar memory, demomakers unlocked resolutions, refresh rates, hardware scrolling, and color depths that IBM never officially documented. This deep hardware manipulation allowed demogroups to outpace official specifications and produce graphics that rivaled dedicated gaming computers like the Commodore Amiga.

The foundation of most VGA hacking was breaking out of IBM’s default "Mode 13h." While Mode 13h offered 320x200 resolution with 256 colors from a palette of 262,144, it utilized a "chained" memory model (Chain-4). Chain-4 forced the hardware to map sequential pixels across four 64KB memory planes automatically, restricting programmers to a single 64KB segment and preventing page flipping. European coders discovered that by clearing the Chain-4 bit in the Sequencer register and the Odd/Even disable bit, they could "unchain" the VGA. This technique exposed the full 256KB of video memory, giving birth to custom planar modes such as "Mode X" (popularized as 320x240 with square pixels). With 256KB accessible, coders gained multiple display buffers, enabling tear-free animations through hardware page flipping.

Access to unchained memory also revolutionized 2D rendering speed. In planar modes, writing a single byte to video RAM could update four adjacent pixels simultaneously using the VGA's internal latch registers and Write Modes (specifically Write Mode 1 and Write Mode 2). Democoders repurposed the Graphics Controller's bit-mask registers and hardware logic functions to perform instantaneous blitting, planar fill operations, and 3D polygon rasterization far faster than pure CPU-to-memory writes would allow.

Beyond memory structure, demogroups directly manipulated the Cathode Ray Tube Controller (CRTC) registers to control the electron beam of analog CRT monitors. Standard PC displays were designed to run at fixed horizontal and vertical sync rates, but demomakers altered parameters like horizontal total, vertical retrace start, and vertical display end. By tweaking these timings, coders forced monitors into non-standard refresh rates up to 70 Hz or higher, eliminated black screen borders (overscan/borderless display), and created smooth, sub-pixel horizontal and vertical hardware scrolling by incrementing the CRT start address register and horizontal pel panning register.

To overcome the 256-color limit without an Amiga-style custom blitter or "Copper" coprocessor, coders perfected raster interrupts through extreme CPU cycle counting. Because standard PC architecture lacked an interrupt tied directly to individual horizontal scanlines, coders polled Input Status Register 1 to wait for the horizontal blanking interval (HBlank). By calculating exact CPU instruction timings down to the clock cycle, programmers altered the Digital-to-Analog Converter (DAC) palette registers mid-screen as the raster beam drew the display. This technique, known as "raster splits" or "copper bars," allowed displays to show thousands of distinct colors on screen simultaneously.

Through these combined techniques, European groups such as Future Crew, Triton, and Orange transformed a rigid, business-oriented display standard into a flexible graphics engine. Demonstrations like Future Crew's 1993 production Second Reality proved that raw, cycle-accurate hardware access could push standard VGA hardware far beyond the boundaries set by IBM engineers.
