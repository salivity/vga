Why VGA Clones Disabled Vertical Retrace Interrupts

When IBM introduced the Video Graphics Array (VGA) standard with the PS/2 line in 1987, the hardware included the capability to generate a CPU interrupt at the start of each vertical blanking interval. Despite this design specification, third-party manufacturers of clone VGA cards frequently left the vertical retrace interrupt disabled by default, made it optional via jumpers, or omitted the physical trace entirely. This article explains the technical constraints and software design patterns that made the vertical retrace interrupt obsolete on PC clones, specifically focusing on ISA bus IRQ scarcity, software reliance on register polling, hardware implementation flaws, and historical precedents.

The Problem of ISA Bus IRQ Scarcity

The original IBM PS/2 architecture utilized the Micro Channel Architecture (MCA) bus, which supported level-triggered, shareable interrupts. In contrast, the vast majority of third-party VGA clone cards were manufactured for the standard Industry Standard Architecture (ISA) bus found in IBM PC/AT compatibles.

The ISA bus used edge-triggered interrupts that could not easily be shared among multiple expansion cards. IBM assigned the display adapter interrupt to IRQ 2, which on the AT architecture was repurposed as the cascade line to the secondary interrupt controller, mapping to IRQ 9. Because ISA systems had a strictly limited pool of interrupts, reserving a dedicated interrupt line for the video card was inefficient. Expansion devices such as network interface cards, sound cards, and SCSI controllers actively competed for IRQ 2/9, forcing manufacturers to avoid assigning an IRQ to the VGA card to prevent hardware conflicts.

The Shift Toward Register Polling

Even when hardware interrupts were functional, real-time graphics programmers largely ignored them. Video games and graphical software required precise synchronization with the display refresh cycle to prevent visual tearing when swapping display buffers or updating palette registers.

Handling synchronization through an interrupt service routine (ISR) introduced noticeable overhead:

  • Saving and restoring CPU register states.
  • Processing interrupt masks on the 8259 Programmable Interrupt Controller (PIC).
  • Latency caused by other system interrupts temporarily disabling the interrupt flag (CLI).

Programmers discovered that polling the VGA hardware directly was faster, more deterministic, and avoided interrupt latency. By reading bit 3 of the Input Status Register 1 (located at I/O port 0x3DA for color systems or 0x3BA for monochrome), software could continuously poll for the vertical blanking interval using a tight loop. Because polling worked universally across all clone hardware without requiring a dedicated IRQ, software developers standardized on this method, eliminating the commercial need for the hardware interrupt.

Silicon Bugs and Errata in Clone Chipsets

To enable the vertical retrace interrupt, software had to clear bit 5 of the Vertical Retrace End Register (CRTC register 0x11) and set bit 4 to clear any pending interrupt status.

Early VGA clone chipsets—such as those produced by Tseng Labs, Trident, Oak Technology, and Cirrus Logic—frequently exhibited errata in their CRTC state machines. On some clone cards, clearing the interrupt flag failed to reset the internal latch reliably, resulting in continuous interrupt requests that locked up the host CPU. On others, the interrupt signal was noisy, generating spurious interrupts. To ensure stability across diverse clone motherboards, manufacturers chose either to ground the interrupt pin on the graphics controller, leave the ISA IRQ line disconnected, or hardwire the feature to an off state.

The Legacy of the Enhanced Graphics Adapter

The practice of abandoning the display interrupt predated VGA. The earlier Enhanced Graphics Adapter (EGA) standard also featured a vertical retrace interrupt routed to IRQ 2. In practice, IBM's own EGA BIOS routinely left this interrupt disabled due to reliability problems and peripheral conflicts on early PC and XT motherboards.

Because the software ecosystem had already adapted to the absence of a reliable video interrupt during the EGA era, the transition to VGA clones inherited the established paradigm: graphics synchronization belonged in software loops, freeing system interrupts for devices that could not operate without them.
