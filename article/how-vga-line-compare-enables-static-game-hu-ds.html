How VGA Line Compare Enables Static Game HUDs

The Video Graphics Array (VGA) Line Compare register provides a hardware-level split-screen mechanism that allows game developers to display a fixed heads-up display (HUD) alongside a smoothly scrolling playfield without consuming CPU cycles. By commanding the VGA cathode ray tube controller (CRTC) to reset its internal memory read address back to zero once the raster scan reaches a specific vertical scanline, the graphics hardware decouples the static HUD elements from the dynamically scrolled world viewport.

The Mechanics of VGA Hardware Scrolling

To scroll a game world smoothly in VGA mode (such as standard Mode 13h or planar Mode X), the display hardware adjusts where in video memory (VRAM) it begins reading pixel data for the frame. Coarse scrolling is achieved by modifying the CRTC Start Address High and Low registers (indices 0x0C and 0x0D), which shifts the start of the frame in multi-pixel or byte increments. Fine scrolling is handled by the Attribute Controller’s Horizontal Pel Panning register (0x33), shifting the display horizontally pixel-by-pixel.

While this allows smooth 360-degree camera movement across a large off-screen map stored in VRAM, it introduces an immediate issue: altering the Start Address shifts every pixel drawn on the display. Without a hardware split, any HUD or status bar drawn in that memory space would drift and scroll along with the scenery. Redrawing the HUD manually every frame using the CPU would cause severe performance drops and visual tearing on vintage hardware.

The Line Compare Registers

The VGA hardware solves this through the Line Compare register. This 10-bit register is split across three CRT Controller locations:

  • Bits 0–7: CRTC Register 0x18 (Line Compare Register)
  • Bit 8: CRTC Register 0x07 (Overflow Register, Bit 4)
  • Bit 9: CRTC Register 0x09 (Maximum Scan Line Register, Bit 6)

Together, these bits represent a target scanline index (from 0 to 1023) within the vertical refresh cycle.

Operation During the Raster Scan

During active display generation, the electron beam scans horizontally across the screen, line by line, from top to bottom. The CRTC maintains an internal vertical line counter that increments at each horizontal blanking interval.

On every scanline, the CRTC hardware compares the current vertical line counter to the 10-bit value stored in the Line Compare registers. Until a match occurs, the memory address counter continues fetching pixel data sequentially, offset by whatever values are loaded into the Start Address and Pel Panning registers.

The moment the vertical line counter equals the value in the Line Compare register, the CRTC automatically triggers two events:

  1. It resets the internal memory address counter to 0x0000.
  2. It resets horizontal pixel panning back to zero (if enabled by bit 5 of the Attribute Controller’s Pel Panning compatibility register).

Memory Organization and HUD Placement

Because the Line Compare event forces the memory fetch pointer to reset to address 0x0000, developers organize VRAM strategically:

  • Static HUD Data: Placed at physical VRAM address 0x0000. Because the fetch address resets to zero and panning is suppressed at the Line Compare trigger, the data located here is rendered completely stationary.
  • Scrolling Playfield: Placed at higher memory offsets (e.g., 0x4000 or higher). The CRTC Start Address registers point to the current camera coordinates within this region.

In the standard hardware configuration, the scrolling viewport renders across the upper part of the screen, and the Line Compare splits the lower portion of the screen to draw a static bottom status bar.

When a game requires the HUD to sit at the top of the screen above a scrolling viewport, developers invert this relationship. The Start Address is pinned to a fixed memory location to draw the static HUD at scanline zero. Developers then use an interrupt—such as a horizontal blank interrupt or a timed timer interrupt synchronized to the bottom scanline of the HUD—to update the Start Address registers mid-frame, or they combine the Line Compare with page-flipping tricks to display the viewport in the lower segment.

Advantages Over Software Blitting

Using the Line Compare register requires zero CPU intervention once programmed for a frame. The display splits cleanly on exact scanline boundaries without timing jitter or raster artifacts. This freed early PC game developers from having to clear and redraw static UI elements every tick, preserving precious CPU execution time for game physics, enemy artificial intelligence, and sprite composition.
