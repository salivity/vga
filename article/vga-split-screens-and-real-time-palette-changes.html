VGA Split Screens and Real-Time Palette Changes

During the peak of the PC demoscene, programmers sought to extract console- and Amiga-like visual effects from standard IBM Video Graphics Array (VGA) hardware without relying on dedicated coprocessors. By synchronizing raster split-screens with mid-frame palette modifications, demo creators bypassed the strict 256-color ceiling of Mode 13h, achieved multi-directional parallax scrolling, and built composite displays with zero software-blending overhead. This combined technique maximized the throughput of limited 16-bit and 32-bit CPUs by delegating color expansion and screen segmentation directly to the CRT controller and digital-to-analog converter.

Overcoming the 256-Color Barrier

Standard VGA Mode 13h offers a resolution of 320x200 pixels with an 8-bit color depth, permitting only 256 simultaneous colors chosen from an 18-bit master palette (262,144 colors). While 256 colors were adequate for basic games, demoscene productions required rich atmospheric gradients, realistic shading, and high-color textures.

VGA lacked a dedicated display coprocessor like the Commodore Amiga's Copper, meaning the main CPU had to handle raster synchronization directly. By polling the VGA Input Status Register 1 (0x3DA) or configuring the programmable interval timer (PIT 8253/8254) to trigger interrupts on specific scanlines, programmers tracked the display's electron beam. During the horizontal blanking interval (H-Blank)—the brief window when the beam resets to the start of the next scanline—coders rapidly rewrote values in the Color Look-Up Table (CLUT) via I/O ports 0x3C8 and 0x3C9.

Altering palette values mid-frame allowed individual scanlines or vertical screen segments to reference unique color maps. This made it possible to display thousands of colors on screen at the same time, producing smooth sky-to-ground backdrops, metallic raster bars, and localized lighting effects without burning CPU cycles on software pixel shading.

Utilizing Hardware Split-Screens

The VGA Cathode Ray Tube Controller (CRTC) contains a dedicated hardware mechanism known as the Line Compare Register (CRTC Index 0x18, with overflow bits in 0x07 and 0x09). When the internal scanline counter matches the value stored in the Line Compare register, the hardware automatically resets the display memory read address back to zero.

Demo coders leveraged this feature to segment the display into distinct horizontal regions without software intervention:

  • Decoupled Viewports: The top portion of the screen could point to an arbitrary offset in video memory (used for smooth, multi-directional scrolling or 3D rendering buffers), while the lower portion remained fixed in place.
  • Overcoming Refresh Overheads: Static user interfaces, text scrollers, and credits could run at different refresh intervals or remain stationary without redrawing pixel data on every frame.

The Power of Combining Both Techniques

While split-screens and palette changes were useful independently, chaining them together solved the architectural bottlenecks of early x86 personal computers:

  1. Independent Color Space Allocation: A dynamic 3D scene or plasma effect requires a broad spectrum of colors (such as deep blues and fiery oranges) to avoid harsh color banding. A static text scroller or HUD sharing the screen would normally compete for those same 256 slots. By firing palette swaps precisely at the hardware split-screen boundary, creators allocated 256 distinct palette indices solely to the dynamic effect, and a completely different set of 256 colors to the static interface below it.
  2. Simulated Hardware Layers: 1990s PC hardware lacked hardware sprites and multiple hardware background layers. By slicing the raster into split sections and cycling palettes within specific scanline bands, coders produced the illusion of independent, layered graphics planes moving at varying depths.
  3. Bandwidth Preservation: Rewriting screen memory (VRAM) across the slow ISA bus was the primary performance bottleneck on 80386 and 80486 systems. Modifying a handful of DAC registers and a CRTC split index required only a few I/O write operations, delivering massive visual transformations at a fraction of the bandwidth cost of a software screen redraw.
