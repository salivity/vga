VGA Split Screen with the CRTC Line Compare Register

This article explains the mechanics of implementing a hardware-level split screen on standard Video Graphics Array (VGA) hardware using the Cathode Ray Tube Controller (CRTC) Line Compare register. It details how the CRTC tracks scanlines, how matching the target scanline forces an internal memory counter reset, and how this mechanism allows developers to display a fixed status bar alongside a scrolling playfield without consuming CPU cycles during rendering.

The Mechanics of VGA Memory Addressing

Under normal operation, the VGA CRTC continuously generates the raster display by fetching pixel data from Video RAM (VRAM). The starting point for this fetch cycle is dictated by the CRTC Start Address High and Low registers (indices 0x0C and 0x0D).

At the beginning of each frame (vertical retrace), the CRTC loads its internal memory address counter with the value stored in the Start Address registers. As the electron beam scans across each horizontal line, this address counter increments sequentially. When software updates the Start Address registers to implement smooth camera movement, the entire screen shifts accordingly.

The Function of the Line Compare Register

To split the screen horizontally, the VGA hardware provides a dedicated register specifically designed to interrupt this continuous address progression. This is the Line Compare register, located primarily at CRTC index 0x18.

Because VGA display modes often exceed 256 scanlines, the Line Compare value is a 10-bit integer distributed across multiple registers:

  • Bits 0–7: CRTC Register 0x18 (Line Compare Register)
  • Bit 8: CRTC Register 0x07 (Overflow Register, Bit 4)
  • Bit 9: CRTC Register 0x09 (Maximum Scan Line Register, Bit 6)

The 10-bit integer defines a specific horizontal scanline index on the display.

The Reset Mechanism

During rendering, the CRTC maintains an internal vertical scanline counter that increments after every horizontal line is drawn. On every scanline, the hardware comparator checks if the current scanline matches the 10-bit value programmed into the Line Compare register.

When a match occurs:

  1. The CRTC automatically resets its internal memory address counter to zero.
  2. For all subsequent scanlines in that frame, video data is fetched starting from memory offset 0x0000, rather than continuing from the previous address.
  3. The hardware resets the Horizontal Pel Panning register (Attribute Controller register 0x33, index 0x13) to zero for the rest of the frame, ensuring that fine-scrolling offsets applied to the top half do not cause horizontal jitter in the bottom half.

Because this reset is handled entirely in hardware at the silicon level, it occurs instantaneously without generating interrupts or requiring CPU intervention mid-frame.

Practical Application

The Line Compare register divides the display into two distinct regions:

  • Top Area (Variable): Starts fetching from the CRTC Start Address (0x0C/0x0D). This region can be scrolled both vertically and horizontally (using fine pel panning) by updating the Start Address and panning registers.
  • Bottom Area (Fixed): Starts fetching strictly from VRAM offset 0x0000 starting at the designated scanline. It remains completely static regardless of how the top area scrolls.

This architecture made the Line Compare register the standard method for rendering stationary heads-up displays (HUDs), inventories, and status bars at the bottom of the screen in MS-DOS action games and RPGs while maintaining high-performance hardware scrolling for the main game world.
