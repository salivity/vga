Syncing Doom's 35 Hz Game Loop to 70 Hz VGA

When id Software developed DOOM, they faced the challenge of aligning a fixed 35 Hz game logic simulation with the PC's standard 70 Hz Video Graphics Array (VGA) vertical refresh rate. Because 70 Hz is exactly double 35 Hz, id Software established an exact 2:1 cadence between the display's vertical retrace and the engine's physics updates. By reprogramming the PC’s internal hardware timer to advance the logic and monitoring the VGA controller's raster beam, the engine ensured smooth motion, tear-free rendering, and deterministic game mechanics on standard DOS hardware.

The 2:1 Hardware Ratio

Standard VGA mode 320x200 (including Mode 13h and tweaked planar variations like "Mode Y") operates with a vertical refresh frequency of approximately 70.086 Hz. This means the electron gun of a CRT monitor redraws the entire screen roughly every 14.28 milliseconds.

John Carmack designed DOOM to run its physics, world simulation, and player inputs at 35 frames (or "tics") per second, giving each game tick a fixed duration of roughly 28.57 milliseconds. Because 70 divided by 35 equals 2, every game simulation tick maps directly to two full vertical refreshes of the VGA monitor.

Reprogramming the Programmable Interval Timer (PIT)

To manage game logic independently of rendering, id Software hooked into the Intel 8253/8254 Programmable Interval Timer (PIT) via IRQ 0.

Normally, the PC BIOS configures PIT Channel 0 to trigger an interrupt at roughly 18.2 Hz. id Software reprogrammed the PIT's frequency divisor to fire at 35 Hz (or a multiple thereof, such as 70 Hz or 140 Hz depending on the version and DOS extender used) using the base clock oscillator frequency of 1.193182 MHz.

Each time the timer fired, it updated a global counter called gametic. The main loop evaluated this counter in a while loop:

while (maketic - gametic > 0) {
    G_Ticker();
    gametic++;
}

If rendering took longer than expected, this fixed-step loop processed multiple simulation ticks back-to-back to ensure the game world never slowed down or lost synchronization.

Polling the Vertical Retrace

To avoid visible visual tearing, buffer flips had to occur during the vertical blanking interval (VBLANK)—the period when the CRT's electron beam turned off to travel from the bottom right of the screen back up to the top left.

DOS games typically lacked hardware-level synchronization APIs, requiring developers to poll the VGA Input Status Register 1 at I/O port 0x3DA. Specifically, Bit 3 of register 0x3DA indicates the retrace status:

  • If Bit 3 is 1, the display is in a vertical retrace.
  • If Bit 3 is 0, the display is actively scanning active video.

A standard assembly routine to wait for the next clean vertical blanking cycle looked like this:

mov dx, 03DAh
WaitNotVsync:
    in al, dx
    test al, 08h
    jnz WaitNotVsync
WaitVsync:
    in al, dx
    test al, 08h
    jz WaitVsync

First, the code waited for any ongoing retrace to finish, then it waited for the next retrace to begin.

Page Flipping vs. Memory Blitting

Depending on the engine revision and rendering mode:

  1. Double Buffering: The engine drew the 3D scene to an off-screen frame buffer located in main system memory. Once the render finished and the 35 Hz tick arrived, the engine waited for the 70 Hz VBLANK signal via port 0x3DA and copied the buffer into VGA Video RAM (located at segment 0xA000).
  2. Page Flipping (Mode Y): When using tweaked 320x200 planar modes, the 256 KB of VGA memory was large enough to hold multiple frame buffers. Instead of copying all 64,000 pixels across the slow ISA bus every frame, the engine drew into an inactive video page and reprogrammed the VGA Start Address Register (0x3D4 index 0x0C and 0x0D) during the vertical retrace, instantly switching the display pointer with zero bus copy overhead.

By binding the page switch or blit to the start of a retrace cycle while running the tick accumulator at 35 Hz, the frame was consistently displayed for exactly two CRT scans, locking the gameplay to a smooth, predictable cadence.
