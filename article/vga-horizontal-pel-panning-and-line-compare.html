VGA Horizontal Pel Panning and Line Compare

This article examines how the Video Graphics Array (VGA) handles smooth horizontal scrolling during a split-screen configuration. It details the specific interaction between the Horizontal Pel Panning register and the CRT Controller Line Compare register, explaining how the VGA hardware prevents lower split screens from unintentionally inheriting horizontal pixel offsets intended only for the top screen.

The Roles of the Registers

In standard VGA architecture, smooth scrolling and screen splitting rely on separate hardware registers:

  • CRT Controller Start Address Registers (CR0C/CR0D): Define the starting byte offset in video memory for scanning the frame.
  • Horizontal Pel Panning Register (AR13): Located in the Attribute Controller, this register shifts the screen display horizontally by 0 to 7 pixels (or 0 to 8 in 9-dot text modes). This fine-tunes scrolling beyond the standard byte boundaries.
  • Line Compare Register (CR18, extended by bits in CR07 and CR09): Defines a specific scanline counter value. When the internal vertical raster counter reaches this value, the internal memory address counter automatically resets to zero, generating a split-screen area commonly used for static heads-up displays (HUDs) or status bars.

The Horizontal Panning Conflict

When the memory address counter resets upon a Line Compare match, the display hardware begins reading from the start of video memory (0x0000) to draw the bottom partition of the screen.

However, byte-level address resetting only solves vertical offset and coarse horizontal alignment. The Horizontal Pel Panning register operates within the Attribute Controller at the pixel output stage, downstream from memory address generation. If left unchecked, any horizontal sub-byte shift applied to scroll the upper window will persist into the lower split screen, causing a static status bar to jitter horizontally by up to 7 pixels.

Hardware Resolution via Attribute Mode Control

To prevent this jitter, the VGA hardware provides a dedicated arbitration bit inside the Attribute Mode Control Register (AR10):

  • Bit 5: Pixel Panning Compatibility (PPC)

The state of Bit 5 dictates how the Line Compare signal interacts with the Horizontal Pel Panning register:

  • Bit 5 = 0 (Disabled): The horizontal pel panning value applies uniformly across all scanlines from top to bottom. The Line Compare match resets the video memory address to zero, but the horizontal pixel offset defined in AR13 remains active for the lower split screen.
  • Bit 5 = 1 (Enabled): When the vertical scanline counter matches the Line Compare register, an internal hardware signal forces the effective horizontal pel panning value to 0 for the remainder of the display frame.

Scanline Execution Cycle

When Bit 5 of AR10 is set to 1, the display cycle executes as follows:

  1. Top Screen Rendering: The frame begins. The VGA applies both coarse byte offsets (CR0C/CR0D) and the fine pixel panning value (AR13). Smooth horizontal scrolling functions normally.
  2. Line Compare Match: The raster beam reaches the scanline specified in the Line Compare register.
  3. Address & Shift Reset: The CRT Controller resets its memory address counter to zero, and the Attribute Controller suppresses the horizontal pel panning value, snapping pixel alignment back to the standard byte boundary.
  4. Bottom Screen Rendering: The lower partition renders stably without horizontal jitter, regardless of the active value inside AR13.
  5. Vertical Retrace: Upon reaching vertical blanking, the suppression clears, restoring the stored AR13 panning value in preparation for the top of the next frame.
