Why VGA Mode X Enabled Smooth Pixel Scrolling

Mode X, an undocumented 320x240 planar tweak of the standard IBM VGA architecture popularized by Michael Abrash, revolutionized PC gaming by unlocking hardware-level capabilities that were inaccessible in the standard linear Mode 13h. Achieving fluid, single-pixel horizontal scrolling had historically been a significant performance bottleneck because copying large blocks of video memory strained early PC processors. Mode X overcame this limitation by combining the VGA’s 256 KB planar memory layout with two distinct hardware display controls: the CRT Controller Start Address registers for coarse scrolling and the Attribute Controller's Horizontal Pixel Panning Register for sub-byte, single-pixel precision.

In standard Mode 13h (320x200 linear), each byte represents a single pixel directly mapped to memory sequentially, and only 64 KB of the VGA's 256 KB memory is exposed. Scrolling in this mode required the CPU to manually redraw or copy large buffers in RAM, a costly operation that made full-screen scrolling sluggish. Furthermore, Mode 13h locked the VGA hardware into chained addressing, disabling many of the controller's built-in panning and multi-page features.

Mode X restored the VGA hardware to its native "unchained" planar state while keeping the 256-color palette. In this mode, the display memory is divided across four parallel 64 KB memory planes. Because every horizontal byte written across the planes addresses four consecutive screen pixels (Plane 0 holds pixels 0, 4, 8; Plane 1 holds 1, 5, 9, and so on), an entire 320x240 screen requires only 19,200 bytes of addressing space. This drastic reduction in address footprint unlocked the full 256 KB of video RAM, allowing developers to allocate off-screen surfaces, virtual playfields, and multiple visual pages for double buffering.

To scroll the screen, developers did not rewrite the frame buffer; instead, they manipulated where the VGA hardware began reading its display data during the vertical retrace interval. Coarse horizontal scrolling was achieved using the CRT Controller (CRTC) Start Address High and Low registers (ports 0x3D4 with indexes 0x0C and 0x0D). Incrementing or decrementing this start address offset shifted the visible viewport across video RAM in four-pixel increments per byte. Because this was handled entirely by the video controller's address counters, shifting the screen four pixels cost virtually zero CPU cycles.

The remaining challenge—scrolling within those four-pixel boundaries—was solved by the Horizontal Pixel Panning Register, located within the VGA's Attribute Controller (port 0x3C0, index 0x33). This hardware register instructed the internal shift registers to delay or advance pixel output by zero to three pixels before transmitting the digital color signals to the Digital-to-Analog Converter (DAC).

By synchronizing the CRTC Start Address register and the Horizontal Pixel Panning register, developers achieved uninterrupted, single-pixel movement. Moving right by one pixel merely required setting the panning register to 1, then 2, then 3. On the fourth pixel, the panning register was reset to 0 while the CRTC Start Address was incremented by one byte. Because the hardware automatically read from the designated memory offset on the subsequent vertical blank, the viewport scrolled smoothly down to the individual pixel without tearing, flickering, or wasting processor cycles on memory copying.
