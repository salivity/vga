VGA Logical Operations for CPU and Memory Latches

The IBM Video Graphics Array (VGA) architecture incorporates dedicated hardware within its Graphics Controller to perform bitwise logical operations between incoming CPU write data and data previously held in internal memory latches. This article explains how this hardware-level raster operation works and details the four specific logical operations supported by the VGA standard: unmodified replace (NOP), AND, OR, and XOR.

The Role of VGA Memory Latches and Logic Units

When the CPU reads a byte from VGA video memory in planar modes, the VGA hardware automatically populates four 8-bit internal latches (one for each of the four 64 KB memory planes), capturing 32 bits of display data simultaneously. When writing data back to video memory in Write Mode 0 or Write Mode 2, the Graphics Controller can combine the CPU's incoming byte with the data residing in these latches before committing the result back to video RAM.

This mechanism is controlled via the Data Rotate Register (Index 03h on the Graphics Controller, accessible through I/O port 0x3CE/0x3CF). Bits 3 and 4 of this register represent the Function Select field, which determines which of the four logical operations is applied across all memory planes.

The Four Logical Operations

1. Unmodified / Replace (00b)

  • Function Select Value: 00b (0 decimal)
  • Operation: Data written without modification
  • Description: In this default mode, no logical manipulation is applied. The rotated CPU data directly passes through the logic unit to overwrite the target plane bytes, subject only to the bit mask and enable set/reset settings. The existing contents of the memory latches are ignored by the ALU, effectively functioning as a standard copy/overwrite operation.

2. Logical AND (01b)

  • Function Select Value: 01b (1 decimal)
  • Operation: Result = (CPU Data) AND (Latch Data)
  • Description: The incoming CPU data is bitwise ANDed with the byte stored in the latch for each respective plane. A pixel bit in video memory will only remain 1 if both the incoming CPU data bit and the latched memory bit are 1. This operation is typically used to clear specific bits, apply transparency masks, or cut silhouettes out of existing graphic planes.

3. Logical OR (10b)

  • Function Select Value: 10b (2 decimal)
  • Operation: Result = (CPU Data) OR (Latch Data)
  • Description: The incoming CPU data is bitwise ORed with the latch data. A pixel bit in video memory becomes 1 if either the CPU data bit or the latched memory bit is set to 1. This is commonly used for combining graphic layers, painting foreground pixels over an existing background without erasing adjacent plane data, or implementing additive color effects.

4. Logical XOR (11b)

  • Function Select Value: 11b (3 decimal)
  • Operation: Result = (CPU Data) XOR (Latch Data)
  • Description: The incoming CPU data is bitwise exclusive-ORed with the latched data. A pixel bit is set to 1 only if the bits from the CPU and the latch differ. Writing identical data with an XOR operation toggles the pixels, making this operation the standard method in legacy VGA programming for drawing reversible overlays, rubber-band selection boxes, and animated mouse cursors without permanently destroying the underlying image data.
