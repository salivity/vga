VGA Palette Glitches and Snow Artifacts Explained

During the late 1980s and early 1990s, the transition from IBM's proprietary graphics hardware to inexpensive, third-party Video Graphics Array (VGA) clones introduced subtle hardware quirks to the PC ecosystem. Among the most noticeable were visual flaws commonly referred to as "snow" or "palette glitches." This article examines why these visual disturbances occurred on early, unbuffered clone cards, exploring the hardware architecture of video memory and the internal palette digital-to-analog converter (RAMDAC), the bus contention that caused pixel corruption, and the software techniques developers used to circumvent these limitations.

The Mechanics of Early VGA Display Architecture

An authentic IBM VGA adapter continuously reads video memory (VRAM) to generate a raster signal for an analog CRT monitor. The graphics controller fetches pixel indices from memory and routes them to the RAMDAC, which translates the indices into red, green, and blue voltage levels via an internal color lookup table (CLUT).

To ensure clean output, the system must juggle two competing demands: the CPU modifying screen contents or palette values, and the RAMDAC constantly reading data to refresh the display in real time. IBM handled this through sophisticated wait-state generation, write buffers, and carefully timed arbitration circuits.

What Causes "Snow" and Palette Glitches?

To produce affordable VGA cards, third-party manufacturers frequently eliminated costly components, opting for unbuffered architectures and single-ported dynamic RAM (DRAM). These cost-cutting measures led directly to two distinct visual defects:

  1. VRAM Memory Snow: When a graphics card lacks sufficient FIFO (First-In, First-Out) buffers or dual-ported VRAM, CPU writes to video memory take direct electrical priority over the controller's screen-refresh reads. If the CPU writes a byte to video memory while the display controller is actively reading the exact same address to draw a scanline, the read cycle is interrupted or corrupted. The monitor renders this corrupted data as fleeting white or multicolored specks across the screen, mimicking the look of static television "snow."

  2. The Palette Glitch (RAMDAC Contention): The VGA palette allows software to redefine 256 colors by writing RGB triplets to I/O ports 0x3C8 and 0x3C9. On fully buffered hardware, writes to these registers are staged so that the internal lookup table is not disturbed mid-scan. On unbuffered or poorly synchronized clone chipsets, writing to the palette registers while the RAMDAC is actively looking up pixel colors disrupts the internal DAC address bus. This collision causes the DAC to temporarily output incorrect voltage levels for several pixels, resulting in horizontal streaks, flashing bands, or flickering colors along the scanline currently being drawn.

Software Workarounds: The Vertical Blanking Interval

Because the underlying issue was a hardware race condition, software developers had to implement strict timing routines to avoid visual artifacts on budget hardware.

The primary solution was synchronizing hardware writes with the monitor's Vertical Blanking Interval (VBLANK):

  • Wait-for-Retrace Loops: Software repeatedly queried the VGA Status Register (port 0x3DA) to detect when the CRT's electron beam finished drawing the frame and began moving back from the bottom of the screen to the top.
  • Timed Updating: Because the beam is turned off during VBLANK, the display controller does not require access to VRAM or the RAMDAC. Developers could safely burst memory changes and palette transitions during this small time window—typically roughly 1 to 1.4 milliseconds—without producing visual noise.
  • Horizontal Blanking (HBLANK): For smaller updates, developers timed writes to the brief pause between individual scanlines, though this required cycle-accurate assembly code.

The Obsolescence of Unbuffered Video Hardware

As memory technology advanced into the early 1990s, manufacturers introduced faster dual-ported Video RAM (VRAM), multi-stage FIFOs, and integrated RAMDACs with internal write staging. These improvements enabled asynchronous access, allowing CPUs to read and write to display memory and palette registers freely without interrupting display generation, permanently eliminating snow and palette glitches from modern graphics hardware.
