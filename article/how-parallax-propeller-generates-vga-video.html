How Parallax Propeller Generates VGA Video

The Parallax Propeller microcontroller generates Video Graphics Array (VGA) signals without dedicated external graphics chips by leveraging its unique multi-core architecture, built-in hardware video generators, and deterministic timing. Through a combination of dedicated 32-bit cores (called "Cogs"), shared Hub RAM, and cycle-exact software instructions, the Propeller can compute complex application logic on certain cores while simultaneously streaming pixel data and synchronization pulses directly to a monitor via simple resistor-ladder digital-to-analog converters (DACs).

Dedicated Video Hardware per Cog

Each of the Propeller's eight Cogs contains its own independent video generator module alongside two phase-locked loop (PLL) counters. This internal hardware is capable of shifting out 2-bit or 4-bit color data at high frequencies matching standard VGA pixel clocks (typically derived from an 80 MHz system clock).

The instruction at the heart of this process is WAITVID (Wait for Video). When a Cog executes WAITVID, it pauses execution until the Cog's video generator is ready for the next slice of pixels, then feeds it a 32-bit pixel pattern and a corresponding color palette. Because this process is integrated into the silicon of every Cog, video generation incurs minimal processing overhead compared to purely software bit-banged approaches.

Multi-Core Division of Labor

Traditional single-core microcontrollers struggle with VGA output because handling timing-critical scanlines, vertical sync (VSync), and horizontal sync (HSync) leaves little to no processing time for user code, often causing visual jitter when interrupts fire.

The Propeller resolves this by designating dedicated Cogs strictly for video timing:

  • The Display Cog: One Cog is isolated to run a continuous loop that calculates scanline timings, asserts HSync and VSync pulses on designated I/O pins, and loads pixel buffers into the Cog's video hardware. Because Propeller Cogs run without conventional operating-system interrupts, the timing remains completely jitter-free.
  • The Application Cogs: The remaining Cogs handle distinct tasks such as reading user inputs, running game logic, or computing physics engines independently, completely isolated from the display routine.

Shared Hub RAM for Frame and Tile Buffers

Data sharing between the logic cores and the video core takes place in the Propeller's shared 32 KB Hub RAM. A round-robin arbiter gives each Cog deterministic, interleaved access to this memory every 16 clock cycles.

Depending on the memory constraints, the video Cog typically reads from the Hub in one of two ways:

  • Bitmap Mode: For lower resolutions (e.g., 256×240 or 320×240), an entire framebuffer can reside in the Hub. Application Cogs draw pixels into this memory, and the video Cog continuously reads and displays it.
  • Tile/Character Mode: To conserve RAM at higher resolutions (such as 640×480 text modes), the Hub stores a character map and font ROM. The video Cog fetches character pointers and reads font pixel lines on the fly as it renders each scanline.

Multi-Cog Interleaving for Higher Performance

While a single Cog is sufficient for standard text modes and low-resolution graphics, developers can gang multiple Cogs together to push higher resolutions or richer color depths. In dual-Cog VGA configurations, one Cog processes even scanlines while a second Cog processes odd scanlines. This parallel pipeline effectively doubles the available processing window per line, allowing the system to achieve higher pixel clock rates, render complex sprites, or generate higher-depth color outputs using standard 8-pin or 16-pin I/O resistor networks.
