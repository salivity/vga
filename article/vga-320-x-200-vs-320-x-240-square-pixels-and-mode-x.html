VGA 320x200 vs 320x240: Square Pixels and Mode X

This article examines the core technical and visual differences between the standard Video Graphics Array (VGA) 320x200 graphics mode and the customized 320x240 resolution, commonly known as "Mode X." It covers how the shift to 320x240 delivers a 1:1 square pixel aspect ratio on standard 4:3 monitors, alters the underlying video memory layout from linear to planar architecture, and unlocks advanced hardware capabilities such as multi-page double buffering and smooth scrolling at the cost of programming complexity.

Pixel Aspect Ratio and Geometry

The standard VGA 256-color mode (BIOS Mode 13h) produces a resolution of 320x200 pixels. When displayed on a standard 4:3 cathode-ray tube (CRT) monitor, 320x200 does not match the physical screen proportions. This mismatch results in non-square pixels with an aspect ratio of roughly 1:1.2, meaning individual pixels are taller than they are wide. Consequently, software must mathematically compensate when drawing geometric shapes; otherwise, circles appear as vertical ellipses, and diagonal lines render with uneven angles.

In contrast, 320x240 has an inherent 4:3 mathematical ratio (\(320 / 240 = 4 / 3\)). Displayed on a 4:3 monitor, this mode yields a true 1:1 square pixel aspect ratio. Square pixels eliminate the need for aspect-ratio correction in software rendering pipelines, simplifying 2D sprite rotations, circle calculations, and 3D projection mathematics.

Memory Architecture: Linear vs. Planar

The most significant architectural divergence between the two modes is how VGA memory is organized:

  • Standard 320x200 (Chained / Mode 13h): Operates in a "chained" mode where hardware logic maps four internal 64 KB memory planes into a single contiguous linear address space at memory segment 0xA000. Each screen byte corresponds directly to one pixel. Plotting a pixel requires a straightforward calculation: Memory Offset = (Y * 320) + X. This simplicity made Mode 13h the default choice for early PC game developers.
  • 320x240 (Unchained / Mode X): Achieved by reprogramming the VGA sequencer and cathode-ray tube controller (CRTC) registers to disable chain-4 mode. This exposes VGA video memory in an "unchained" planar structure. Instead of a linear sequence, four consecutive horizontal pixels reside at the same memory address across four distinct hardware planes (Plane 0, Plane 1, Plane 2, and Plane 3). Drawing a specific pixel requires selecting the target plane using the VGA Map Mask register before writing the byte.

Video RAM Utilization and Page Flipping

A single 320x200 frame requires 64,000 bytes (\(320 \times 200\)), which roughly fills the 64 KB address window exposed by Mode 13h. Because standard Mode 13h addresses memory as a single 64 KB block, the remaining 192 KB of a standard 256 KB VGA adapter is left inaccessible without complex register hacking. This restricts developers to a single frame buffer in video RAM; creating smooth animation generally requires drawing to a buffer in system RAM and copying the entire screen during the vertical retrace interval.

A 320x240 frame requires 76,800 bytes (\(320 \times 240\)). Because unchained planar mode exposes all 256 KB of video memory, the developer can fit up to three complete 76,800-byte video pages directly inside video RAM. This allows true hardware page flipping (double or triple buffering). The application can render to an off-screen page while the display controller outputs the current page, switching the active display pointer instantly during the vertical blanking interval to completely eliminate visual tearing without high-bandwidth system-to-video RAM copies.

Performance and Implementation Trade-offs

The planar layout of 320x240 introduces both performance costs and optimization opportunities:

  • Pixel Plotting Overhead: Setting single, random pixels is slower in 320x240 than in 320x200 because the CPU must execute I/O port writes to select the appropriate plane before each memory write.
  • Parallel Write Speeds: When manipulating four adjacent pixels that share the same color or when copying graphic blocks aligned to 4-pixel boundaries, the CPU can configure the VGA Map Mask to write to all four planes simultaneously with a single memory write. This enables block-fill and sprite-rendering operations that can run up to four times faster than identical operations in linear Mode 13h.
  • Hardware Scrolling: The planar structure and surplus video memory in 320x240 allow developers to use the VGA's built-in start address and horizontal panning registers to achieve multi-directional, sub-pixel smooth scrolling entirely in hardware.
