FPGA Emulation of IBM VGA Chip Registers

Emulating the full register set of an IBM Video Graphics Array (VGA) chip on an FPGA involves synthesizing the legacy indexed I/O architecture, enforcing hardware quirks and access protections, and bridging asynchronous CPU bus cycles with synchronous pixel generation pipelines. Because the original VGA standard relied heavily on multiplexed I/O ports and shared state machines across distinct functional sub-units, the FPGA must capture exact hardware behaviors—including indexed addressing, write-protection masks, toggle states, and clock-domain crossing—using custom hardware description language (HDL) logic blocks and internal register arrays.

I/O Port Decoding and Bus Interfacing

The original IBM VGA exposes its configuration via a limited range of x86 I/O space addresses, primarily within the 0x3B0 to 0x3DF ranges (varying between monochrome and color emulation modes). An FPGA interface block continuously samples the host bus (such as ISA, PCI, or an internal SoC bus like AXI or Wishbone). Address decoding logic monitors chip-select, read/write strobes, and the address lines to identify accesses targeting VGA space.

When a transaction is detected, the FPGA determines whether the operation targets an external register (such as the Miscellaneous Output Register at 0x3C2) or an indexed register file. Because CPU bus operations run asynchronously to the internal video clocks, incoming control signals and data are latched through synchronizers or processed using handshaking logic to prevent metastability.

Implementing the Five Core Indexed Register Blocks

The core functionality of a VGA chip is divided into five main sub-controllers, four of which use an "Index/Data" pair scheme to conserve host I/O space:

  1. Sequencer Registers (SR): Accessed via index port 0x3C4 and data port 0x3C5. The Sequencer controls clock dividers, character map selections, and memory plane masking. In HDL, this is implemented as an array of registers addressed by a 3-bit internal index pointer register.
  2. CRT Controller Registers (CRTC): Mapped to 0x3D4/0x3D5 (color mode) or 0x3B4/0x3B5 (mono mode). The CRTC dictates raster timings, blanking intervals, cursor placement, and vertical/horizontal synchronization.
  3. Graphics Controller Registers (GR): Accessed at 0x3CE/0x3CF. These registers govern bit-masking, read/write modes (Modes 0–3), rotation, and planar data latches between the CPU and video memory.
  4. Color Palette / DAC Registers: Accessed through ports 0x3C6 (PEL Mask), 0x3C7 (Read Index / State), 0x3C8 (Write Index), and 0x3C9 (Data). Because palette values consist of 18-bit RGB values (6 bits per channel) written across three consecutive cycles to 0x3C9, the FPGA implements a 2-bit state machine (Red, Green, Blue) that increments the internal DAC SRAM address only after the third byte is transferred.
  5. Attribute Controller Registers (AR): Handled distinctly due to its shared dual-mode port.

Replicating VGA Hardware Quirks and State Machines

A compliant VGA implementation requires emulating behaviors that differ from modern standard bus interfaces:

  • The Attribute Controller Flip-Flop: The AR uses port 0x3C0 for both the index register and the data register. The FPGA models this using a 1-bit state flip-flop. Reading the Input Status 1 register (0x3DA or 0x3BA) clears this flip-flop to 0. When cleared, the next write to 0x3C0 is treated as an index. Once written, the flip-flop toggles to 1, meaning the subsequent write is routed as data.
  • Write Protection Bitfields: Register 0x11 of the CRTC contains a write-protect bit (bit 7). When asserted, writes to CRTC registers 0x00 through 0x07 must be ignored by the FPGA logic to prevent software from altering critical CRT sync parameters. The FPGA enforces this via conditional write-enable logic on those specific register array elements.
  • Read-Only and Write-Only Asymmetries: Some VGA registers share an I/O port address but represent entirely different internal entities depending on the operation. For example, writing to 0x3C2 modifies the Miscellaneous Output Register, whereas reading from 0x3C2 accesses the Input Status 0 Register. The FPGA HDL directly separates read multiplexers from write-latch decoders according to the bus read/write strobes.

Cross-Clock Domain Synchronization

The register file lives primarily in the host CPU bus clock domain, but the values it contains directly drive raster timing counters and video data generation, which run on distinct pixel clock domains (typically 25.175 MHz for standard VGA or 28.322 MHz for 720-pixel text modes).

To ensure stability, the FPGA holds the current register values in flip-flops or distributed RAM. Registers that affect screen geometry—such as start addresses, line compares, and horizontal/vertical retrace boundaries—are often shadowed. The FPGA latches these parameters into shadow registers exclusively during horizontal or vertical blanking intervals to prevent visual tearing or timing collapse mid-frame.
