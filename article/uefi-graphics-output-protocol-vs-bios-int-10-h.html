UEFI Graphics Output Protocol vs BIOS INT 10h

This article explores the transition from legacy Video Graphics Array (VGA) BIOS INT 10h interrupts to the Unified Extensible Firmware Interface (UEFI) Graphics Output Protocol (GOP). It examines how both systems initialize display hardware during pre-boot, compares their underlying architectures and memory models, and outlines why GOP has replaced INT 10h to support modern, high-resolution computing environments.

The Role of Legacy BIOS INT 10h

In traditional PC architecture, the basic input/output system (BIOS) relied on interrupt vector INT 10h for video services. When a system powered on, the CPU operated in a 16-bit real-mode environment. The motherboard BIOS executed the video card's Video BIOS (VBIOS) option ROM, establishing INT 10h as the software interrupt interface for all screen output prior to the operating system loading.

Key characteristics of INT 10h include:

  • 16-Bit Real-Mode Dependency: All calls required the processor to be in 16-bit real mode or required an x86 emulator if accessed from protected or long mode.
  • Hardware Text Modes: It provided native hardware-rendered text modes (such as standard 80x25 character mode) and basic raster modes (such as VGA 320x200 with 256 colors).
  • Segmented Memory and Bank Switching: Because real mode addresses only up to 1 MB of memory, video memory was mapped to a tiny 64 KB or 128 KB window (typically starting at segment A000h or B800h). Higher resolutions introduced by VESA BIOS Extensions (VBE) required complicated bank switching to update the display.
  • x86 Architecture Lock-in: The 16-bit x86 machine code in the VBIOS meant that non-x86 architectures could not natively initialize standard PC graphics cards.

The Role of UEFI Graphics Output Protocol (GOP)

The Graphics Output Protocol (GOP) is the standard display mechanism defined by the UEFI specification. GOP replaces the legacy VBIOS and INT 10h routines with a modern, C-callable protocol that acts as an abstraction layer between pre-boot software and the graphics hardware.

Key characteristics of GOP include:

  • 32-Bit and 64-Bit Native Execution: GOP drivers run directly in protected mode or 64-bit long mode. The CPU never drops down to 16-bit real mode to draw pixels.
  • Architecture Agnostic: Written in standard UEFI-compliant C, GOP drivers work across diverse CPU architectures, including x86-64, ARM, and RISC-V, without platform-specific machine code constraints.
  • Linear Framebuffer: GOP provides a flat, linearly mapped memory space. The operating system bootloader or firmware writes directly to 32-bit pixel buffers (typically RGB or BGR format) without memory segmentation or bank switching.
  • No Native Text Mode: GOP does not provide an integrated text terminal. All console output is rendered by drawing glyphs onto the graphical framebuffer via software font engines.

Functional Comparison: GOP vs. INT 10h

Execution Environment 16-bit Real Mode 32-bit / 64-bit Flat Mode
Interface Style Software interrupts (INT 10h) Function pointers via protocol interface
Memory Addressing Segmented memory, banked access Flat, direct linear framebuffer

Maximum Display Capabilities Limited; high resolutions require VBE Native support for high resolutions (e.g., 4K, 8K, ultrawide)
OS Graphics Handoff Screen flicker during mode switches Seamless, flicker-free transitions

Why GOP Replaced INT 10h

The transition to GOP eliminated major performance bottlenecks and architectural constraints. Because INT 10h relied on 16-bit interrupts, early boot processes suffered from slow video drawing and were incapable of driving modern ultra-high-definition monitors efficiently during boot.

GOP enables seamless boot routines. Instead of resetting the video adapter and causing the screen to flash black when transitioning from the firmware to the operating system kernel, GOP provides the OS with the physical base address of the active framebuffer. The operating system can continue drawing on the existing canvas until its dedicated, high-performance GPU drivers take control.
