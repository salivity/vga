How Early ISA Cards Matched PS/2 VGA Performance

When IBM introduced the Video Graphics Array (VGA) standard in 1987 alongside the PS/2 family, it set a new visual benchmark by integrating graphics directly onto the motherboard using high-speed bus architectures. Third-party manufacturers faced the challenge of delivering equivalent performance on the slower, legacy Industry Standard Architecture (ISA) bus found in IBM PC/AT clones. This article examines the architectural bottlenecks of the ISA bus and the specific engineering techniques—including 16-bit memory access, write buffers, BIOS shadowing, and early controller-level raster operations—that allowed third-party ISA add-in boards to replicate and eventually surpass IBM's integrated PS/2 VGA output.

The PS/2 Advantage and the ISA Bottleneck

IBM's original VGA was integrated directly into the system boards of the PS/2 Model 50 and above, interfacing over the proprietary 16-bit or 32-bit Micro Channel Architecture (MCA) bus. This integration provided the graphics controller with low-latency access to the CPU and system memory with minimal bus wait states.

In contrast, standard IBM PC/AT compatibles relied on the ISA bus, which ran at a sluggish 8 MHz and typically enforced multiple wait states per transaction. Early attempts to adapt VGA to standard expansion cards also suffered from backward-compatibility constraints, initially limiting memory and BIOS transfers to an 8-bit data path. Because graphics data throughput was critical for smooth redrawing and fast scrolling, ISA-based systems were at a severe structural disadvantage.

16-Bit Memory and I/O Paths

The first major breakthrough for ISA board manufacturers—led by companies such as Tseng Labs, Paradise Systems (Western Digital), and Video Seven—was the development of true 16-bit ISA interfaces. By splitting the standard VGA memory window (0xA0000–0xBFFFF) and I/O addresses into dual-byte transfers, these controllers doubled the theoretical data transfer rates between the CPU and video memory.

To maintain compatibility with legacy software and older PC/XT architectures, these chipsets incorporated dynamic bus sizing. The controllers automatically detected whether they were installed in an 8-bit or 16-bit slot and negotiated the transaction size accordingly, eliminating compatibility concerns while maximizing throughput on 80286 and 80386 systems.

Hardware Write Buffers and FIFOs

A significant source of latency on early graphics boards was the conflict between the display refresh circuitry reading from Video RAM (VRAM/DRAM) and the host CPU writing new pixel data. If the memory was busy scanning out an image to the CRT monitor, CPU write cycles were forced to stall.

Add-in board makers countered this by implementing hardware write buffers and first-in, first-out (FIFO) queues directly on the VGA controller silicon. These buffers allowed the CPU to dump pixel writes at the full speed of the ISA bus without waiting for the onboard memory cycle to complete. The graphics controller then committed the buffered data to display memory during blanking intervals or idle memory cycles, drastically reducing CPU wait states.

Video BIOS Shadowing

IBM’s integrated VGA benefited from rapid BIOS execution because the routines were integrated into the primary motherboard ROM or mapped directly to fast system logic. Standard ISA add-in cards relied on slower, 8-bit or 16-bit EPROM chips mapped into the upper memory area (C0000–C7FFF). Standard DOS software and early graphical environments relied heavily on software interrupt calls (INT 10h) handled by this ROM, creating a substantial performance bottleneck.

ISA card developers combated this by pioneering video BIOS shadowing. Graphics utility drivers and motherboard chipsets copied the contents of the slow expansion ROM directly into high-speed system RAM, subsequently remapping the memory addresses. Running the video BIOS out of 32-bit or zero-wait-state system memory dramatically accelerated text-mode rendering, cursor movement, and screen-clearing operations.

On-Chip Logic and Memory Interleaving

To reduce the amount of data that needed to cross the ISA bus in the first place, chipmakers enhanced the internal logic of their graphics controllers. Instead of requiring the CPU to read a byte of video memory, modify it in registers, and write it back across the ISA bus, controllers like the Tseng Labs ET3000 and ET4000 incorporated hardware-level bit-masking, barrel shifters, and raster operations (such as AND, OR, and XOR) directly on the chip.

Furthermore, card manufacturers replaced slow standard DRAM configurations with dual-bank interleaved memory and Fast Page Mode (FPM) DRAM. By accessing memory across interleaved banks, the controller could alternate read and write operations without suffering standard pre-charge delays, keeping memory bandwidth high enough to service high-resolution refresh rates while simultaneously accepting CPU commands. Through these integrated architectural innovations, 16-bit ISA VGA boards matched, and in many benchmarks exceeded, the throughput of IBM's original integrated PS/2 graphics.
