How Software Detected Genuine IBM VGA vs Clone Cards

During the late 1980s and early 1990s, the IBM Video Graphics Array (VGA) standard established the baseline for PC graphics, triggering an influx of reverse-engineered clone adapters from third-party manufacturers. To optimize graphics routines, handle proprietary extended modes, and mitigate clone-specific bugs, programmers needed reliable methods to identify the hardware running their code. Developers differentiated genuine IBM VGA hardware from low-cost clone boards through BIOS inspection, testing reserved register bits, probing vendor-specific unlock registers, and evaluating hardware-level timing quirks.

BIOS String and Copyright Inspection

The simplest method used to detect genuine IBM hardware was reading the video BIOS ROM located at memory segment C000h.

Genuine IBM adapters featured distinct copyright notices and signature strings within the first few hundred bytes of this segment (such as "IBM" or specific IBM part numbers). Third-party vendors could not legally duplicate IBM's copyrighted BIOS code, so companies like Tseng Labs, Trident, Cirrus Logic, Oak Technology, and Western Digital/Paradise included their own copyright banners and identifiers.

While querying these strings was fast, it was not foolproof; low-quality clones occasionally altered their ROM text to spoof system software, leading developers to rely on low-level register tests instead.

Unused and Reserved Register Bit Masking

Genuine IBM VGA hardware relied on custom ASICs that strictly implemented register bit widths according to original IBM specifications. In many standard VGA registers, certain bits were officially marked as unused or reserved, and genuine IBM hardware hardwired these bits to logic low (0) when read.

Clone manufacturers often used standard gate arrays or memory chips that did not mask these unused bits. Developers could:

  1. Write a test byte with all bits high (0xFF) to a specific register (such as the Cathode Ray Tube Controller (CRTC) or Sequencer registers).
  2. Read the value back from the port.
  3. Apply a bitwise AND mask to check if reserved bits retained the written value.

On genuine IBM silicon, the reserved bits always returned 0. If any reserved bits returned 1, software knew the card was a third-party clone.

CRTC Register Write Protection Behavior

The IBM VGA's CRTC contains a write-protect mechanism via bit 7 of register 11h (Vertical Retrace End Register). When set, it write-protects CRTC registers 00h through 07h to prevent software from corrupting critical monitor timing signals.

Clones frequently exhibited minor discrepancies in how this write-protection was handled:

  • Some budget clone chipsets failed to protect all eight registers.
  • Other clones implemented write protection that required an additional proprietary register to be toggled first.
  • Certain clones inverted the behavior of bit 7 or left registers 00h–07h writable at all times.

Developers tested this behavior by attempting to write altered timing parameters to protected registers while bit 7 was set. If the values changed, the adapter was flagged as non-IBM hardware.

Probing Extended "Unlock" Registers

As clone vendors sought to outperform IBM, they added extended video modes (Super VGA) and proprietary accelerated features. To prevent legacy software from accidentally altering extended configurations, clone manufacturers required software to issue an "unlock" sequence to a proprietary I/O port before accessing extended registers.

Developers probed for these chipsets by attempting vendor-specific unlock sequences:

  • Tseng Labs (ET3000/ET4000): Tested by writing unlock keys to port 3CDh or 3BFh.
  • Trident (8800/8900): Tested by toggling register 0Bh of the Sequencer (port 3C5h) to switch between old and new register addressing modes.
  • Paradise / Western Digital: Tested by unlocking the PR0–PR5 registers via port 3CEh index 0Fh.

If the board accepted the unlock sequence and successfully allowed read/write operations on extended registers, developers identified the exact clone chipset. If the board ignored all known unlock mechanisms, behaved strictly within standard VGA boundaries, and exhibited no extra memory banks, it was classified as either a genuine IBM VGA or a standard-compliant clone.

DAC Read/Write State and Attribute Controller Flip-Flop

The genuine IBM VGA used an INMOS INM6084 (or functional equivalent) Color Look-Up Table (DAC). The DAC state register at port 3C7h returns the current operation mode (read or write) in bits 0 and 1. Due to differences in how clone manufacturers implemented the internal state machine for DAC addressing, the status returned on port 3C7h immediately after writing an address did not always match the behavior of genuine IBM silicon.

Similarly, the Attribute Controller at port 3C0h relies on an internal toggle (flip-flop) to switch between accepting index and data writes, which is reset by reading input status register 1 (3DAh). Minor differences in how clones cleared or toggled this internal flip-flop under rapid I/O operations gave software another hardware-level fingerprint to distinguish IBM hardware from clones.
