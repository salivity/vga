How VGA Write Modes 0 Through 3 Work

The Video Graphics Array (VGA) architecture relies on a specialized Graphics Controller to translate standard 8-bit CPU memory writes across four parallel 64 KB memory planes (Planes 0 through 3). Because a single CPU write addresses multiple planes simultaneously, the VGA provides four distinct hardware write modes—Modes 0, 1, 2, and 3—selected via bits 0–1 of the Graphics Mode Register (Index 05h). Each mode alters the data pipeline between the CPU, the 32-bit internal latches, and the color planes, enabling optimized operations ranging from general-purpose updates and high-speed memory copies to packed-pixel manipulation and fast font rendering.

Internal Architecture Overview

Every byte-level write passes through several functional hardware blocks within the VGA Graphics Controller:

  • Internal 32-Bit Latches: When the CPU reads a VRAM address, one byte from each of the four planes is loaded into four internal 8-bit latches. These latches can mix with incoming CPU write data.
  • Data Rotate Block: Rotates CPU data right by 0–7 bits, determined by the Data Rotate Register (Index 03h).
  • Arithmetic Logic Unit (ALU): Performs bitwise operations (NOP, AND, OR, XOR) between the target data and the contents of the latches (configured via Index 03h).
  • Bit Mask Register (Index 08h): Selects whether each bit position in a plane byte receives the ALU output (bit set to 1) or retains the latch value (bit set to 0).
  • Sequencer Map Mask (Index 02h): Acts as a global gatekeeper, choosing which of the four planes are updated during the write cycle.

Write Mode 0: Direct Write with Rotation and ALU Operations

Write Mode 0 is the default and most versatile mode, commonly used for standard rendering, bit-blitting, and partial updates.

  1. CPU Input & Rotation: The CPU writes an 8-bit value, which is rotated right by the value in the Data Rotate Register.
  2. Set/Reset Multiplexer: For each plane, the Graphics Controller checks the Enable Set/Reset Register (Index 01h):
    • If disabled (0), the rotated CPU byte is passed forward to that plane.
    • If enabled (1), the corresponding bit from the Set/Reset Register (Index 00h) is expanded across all 8 bits (e.g., bit value 1 becomes 0xFF, 0 becomes 0x00), discarding the CPU data for that plane.
  3. ALU Operation: The selected byte passes through the ALU, combining logically with the existing byte in that plane's latch according to the configured raster operation (NOP, AND, OR, XOR).
  4. Bit Masking: The Bit Mask Register selects on a per-bit basis between the output of the ALU and the byte held in the latch.
  5. Plane Write: The resulting byte is committed to memory for any plane enabled by the Sequencer Map Mask.

Write Mode 1: High-Speed VRAM-to-VRAM Copy

Write Mode 1 bypasses the CPU data bus entirely to achieve rapid memory-to-memory block transfers.

  1. Latch Retention: A preceding CPU read from source VRAM populates the four 8-bit internal latches with 32 bits of total plane data.
  2. Direct Latch Write: When the CPU issues a write to destination VRAM in Mode 1, the CPU's written byte value is completely ignored.
  3. Plane Write: The latched data is written directly into Planes 0 through 3 at the target address, controlled strictly by the Sequencer Map Mask.

Because Write Mode 1 does not use the ALU, Data Rotate, or Bit Mask units, it can duplicate 4 bytes of planar data in a single CPU write cycle, effectively quadrupling copy throughput.

Write Mode 2: Color Fill and Packed-Pixel Expansion

Write Mode 2 maps packed 4-bit color values to individual planes, making it ideal for drawing solid-color pixels or horizontal spans without manually splitting colors across planes in software.

  1. Bit Expansion: The CPU writes an 8-bit value, but only bits 0 through 3 are used. Each bit represents a color index for a specific plane:
    • Bit 0 expands across all 8 bits for Plane 0 (0x00 or 0xFF).
    • Bit 1 expands across all 8 bits for Plane 1.
    • Bit 2 expands across all 8 bits for Plane 2.
    • Bit 3 expands across all 8 bits for Plane 3.
  2. ALU Operation: Each expanded 8-bit plane value is processed through the ALU alongside its corresponding latch contents.
  3. Bit Masking: The Bit Mask Register determines which horizontal pixel positions receive the expanded color versus retaining their existing latch values.
  4. Plane Write: Planes enabled by the Sequencer Map Mask write the masked results to VRAM.

This mode enables 8 pixels to be updated to a uniform 16-color value in one CPU write by setting the desired pixel locations in the Bit Mask Register.

Write Mode 3: Patterned Bitmask and Font Rendering

Write Mode 3 is tailored for font expansion and pattern drawing, combining incoming CPU data directly into the masking logic.

  1. CPU Rotation and Mask Generation: The CPU writes an 8-bit byte (such as a font character row), which is rotated by the Data Rotate Register and then bitwise ANDed with the Bit Mask Register. This generated value becomes the active bit mask for the operation.
  2. Data Source: Unlike Mode 0, the data written to the planes does not originate from the CPU. Instead, the 8-bit value for each plane is derived entirely from that plane's bit in the Set/Reset Register (Index 00h), expanded across all 8 bits.
  3. ALU Operation: The expanded Set/Reset data is combined with the latches via the ALU.
  4. Dynamic Masking: The active bit mask generated in Step 1 selects between the ALU output and the original latch data for each bit.
  5. Plane Write: Enabled planes write the combined result to memory.

Write Mode 3 allows software to apply arbitrary foreground colors to monochrome glyphs or stencils in a single write operation without having to rewrite the Bit Mask Register for every byte.
