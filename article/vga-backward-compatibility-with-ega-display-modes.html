VGA Backward Compatibility With EGA Display Modes

When IBM introduced the Video Graphics Array (VGA) standard in 1987 with the PS/2 line of computers, ensuring backward compatibility with the Enhanced Graphics Adapter (EGA) was essential for user adoption. VGA maintained this compatibility through a combination of hardware-level register supersets, planar memory architecture, scan-line adjustments, digital-to-analog palette emulation, and extensive BIOS support. This allowed existing DOS software designed for EGA hardware to run seamlessly on newer VGA systems without modification.

Register-Level Architecture and Superset Design

VGA achieved hardware compatibility primarily by implementing the EGA register architecture as a baseline. The VGA hardware featured the same four internal functional blocks found in EGA: the Sequencer, the Cathode Ray Tube Controller (CRTC), the Graphics Controller, and the Attribute Controller.

Rather than replacing these components, IBM expanded them. VGA preserved the register addresses and bit definitions used by EGA, meaning software that bypassed the BIOS to write directly to hardware I/O ports (such as 0x3C0 to 0x3DF) continued to function as expected. When an application configured these registers for an EGA mode, the VGA chip functioned in a strict EGA emulation state.

Planar Memory Mapping

EGA introduced a planar memory architecture, dividing its 256 KB memory into four distinct 64 KB memory banks (planes) accessible at memory segment 0xA000. Each plane stored specific color bit information (red, green, blue, and intensity) for 16-color graphics modes.

VGA retained this exact four-plane structure and supported the same memory write and read modes (Modes 0 through 3). Because memory addressing and bit-plane arrangements remained identical, EGA software that manipulated display memory directly could read and write pixel data on a VGA card without alteration.

Video Timings and Scan-Line Handling

One major hardware difference between EGA and VGA was the monitor interface and horizontal scan rates. EGA monitors operated at horizontal sync frequencies of 15.7 kHz (for 200-line modes) and 21.8 kHz (for 350-line modes). VGA monitors, by contrast, were fixed-frequency analog monitors operating at approximately 31.468 kHz, rendering vertical resolutions of 400 and 480 lines.

To display EGA modes on 31.5 kHz analog displays, VGA adapted the video timings internally:

  • 200-Line Modes: For legacy 200-line modes (such as 320x200 or 640x200), VGA used hardware double-scanning. The hardware scanned each raster line twice, turning 200 lines of data into 400 visible lines at 70 Hz.
  • 350-Line Modes: For EGA’s native 640x350 mode (Mode 10h), VGA altered the vertical sync and blanking parameters to center the 350 lines within a 400-line vertical timing framework, allowing it to sync properly with the 31.5 kHz monitor.

Color Palette Translation

EGA output a digital RGBI/6-bit signal capable of displaying 16 simultaneous colors from a palette of 64 colors. VGA, conversely, output an analog RGB signal connected to a digital-to-analog converter (RAMDAC) with an 18-bit color space (262,144 colors).

To preserve the appearance of EGA software, the VGA Attribute Controller maintained the original 16-entry palette register table. When an EGA mode was initialized, these registers were loaded with indices that pointed to specific RAMDAC color registers. The RAMDAC was pre-programmed with RGB values matching the exact intensities and hues of the 64 EGA colors, ensuring color fidelity on analog screens.

BIOS Interrupt 10h Support

At the software layer, the VGA BIOS provided complete backward compatibility for BIOS Interrupt 10h calls. Standard EGA video modes—such as Mode 0Dh (320x200 16-color), Mode 0Eh (640x200 16-color), and Mode 10h (640x350 16-color)—were implemented directly in the VGA BIOS routines. When an application called INT 10h, AH=00h to request an EGA mode, the VGA BIOS automatically handled register setup, scan line parameters, and color palette assignment to replicate the target environment.
