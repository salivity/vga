How VGA Hardware Generates Blinking Text

The Video Graphics Array (VGA) hardware generates the blinking text attribute using a combination of dedicated video memory attribute bytes, an internal frame counter derived from the vertical sync signal, and digital multiplexing within the Attribute Controller. Instead of requiring the central processing unit (CPU) to continually rewrite video RAM to toggle characters on and off, the VGA display pipeline manages this effect entirely in silicon. This article explains the internal registers, timing counters, and pixel logic that make hardware text blinking possible in classic VGA architecture.

Text Mode Memory and the Attribute Byte

In standard VGA text modes (such as 80x25 Mode 03h), video memory represents each onscreen character cell using two sequential bytes:

  1. Character Code: An 8-bit ASCII or font-index value stored at an even memory address.
  2. Attribute Byte: An 8-bit metadata byte stored at the adjacent odd memory address.

The 8-bit attribute byte defines the cell's visual properties:

  • Bits 0–3: Foreground color (16 selectable colors).
  • Bits 4–6: Background color (8 selectable colors).
  • Bit 7: Controls either high-intensity background or hardware blinking.

The Attribute Controller Mode Register

The behavior of Bit 7 in the attribute byte is governed by the Attribute Controller (ATC). The VGA programmer accesses the ATC through I/O port 0x3C0. Within the ATC, Attribute Mode Control Register (Index 0x10) contains a dedicated toggle at Bit 3 (Blink / Intensity):

  • When Bit 3 is set to 0, Bit 7 of the cell attribute acts as a high-intensity background selector, allowing 16 distinct background colors and disabling blinking entirely.
  • When Bit 3 is set to 1, Bit 7 is configured as the Blink Enable flag, restricting the background to 8 colors and activating the hardware blink circuit for that character.

Frame Counters and Blink Timing

VGA hardware produces the blink rate by tapping into its internal timing logic. Standard VGA text mode operates at a refresh rate of approximately 70 Hz (720×400 resolution at 70.087 Hz).

Inside the VGA Sequencer and Cathode Ray Tube Controller (CRTC), the vertical retrace interrupt (vertical sync) pulses once at the end of every rendered frame. A dedicated hardware counter divides this vertical sync frequency down by a factor of 16 or 32:

  • A common VGA implementation toggles the internal blink state every 16 or 32 vertical sync intervals.
  • At 70 Hz, dividing by 32 produces a complete blink cycle (one "on" phase and one "off" phase) roughly every 0.9 to 1.8 seconds, yielding a standard blink frequency of approximately 1.88 Hz to 3.75 Hz.

This counter generates a binary square-wave signal (BLINK_CLK), which alternates between logical high and logical low without consuming CPU cycles.

Pixel Serialization and Multiplexing

During screen refresh, the VGA pipeline simultaneously fetches the character byte and the attribute byte from video RAM:

  1. The Character Generator uses the character byte and the current scanline row to extract a 1-byte row slice from the font glyph in memory.
  2. The Serializer (Shift Register) converts this byte into a stream of 1-bit pixel pulses (where 1 represents foreground and 0 represents background).
  3. The pixel stream and the attribute byte enter the Attribute Controller Color Multiplexer.

When the multiplexer encounters a character cell where attribute Bit 7 is set to 1 (and ATC Register 0x10, Bit 3 is active), it combines the pixel stream with the internal BLINK_CLK state:

  • When BLINK_CLK is HIGH (Blink Phase "On"): The multiplexer routes the foreground color index to the Palette RAM (DAC) whenever the serializer outputs a 1. The character displays normally.
  • When BLINK_CLK is LOW (Blink Phase "Off"): The hardware logic gates the serializer output. Instead of passing the foreground color index to the DAC, the logic forces the foreground pixels to inherit the background color index stored in Bits 4–6 of the attribute byte.

Because the foreground pixels match the background color during the low phase of the clock, the character temporarily vanishes into the cell background. When BLINK_CLK returns to high, the foreground pixels are restored, producing a smooth, hardware-driven blinking effect across the screen.
