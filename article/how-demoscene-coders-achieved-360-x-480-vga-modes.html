How Demoscene Coders Achieved 360x480 VGA Modes

This article explores how early PC demoscene programmers manipulated IBM VGA hardware registers to bypass standard BIOS video limits and generate non-standard 360x480 resolution modes in 256 colors. By selecting alternative master dot clocks, disabling memory chaining, and reprogramming the Cathode Ray Tube Controller (CRTC), coders pushed standard cathode-ray monitors beyond their documented specifications without exceeding the monitor's analog scanning limits.

Exploiting the 28 MHz Dot Clock

The IBM Video Graphics Array (VGA) chipset featured two master hardware crystal oscillators: 25.175 MHz and 28.322 MHz. Standard 320-pixel graphics modes (such as BIOS Mode 13h) and 640-pixel modes (Mode 12h) relied on the 25 MHz clock. The 28 MHz clock was normally reserved for 80-column text mode (720x400), where each character cell spanned 9 dots across rather than 8.

Demoscene coders accessed the faster 28.322 MHz oscillator by writing directly to the Miscellaneous Output Register at I/O port 0x3C2. Setting the clock selection bits from 00 (25 MHz) to 01 (28 MHz) forced the graphics pipeline to pump pixels out at the higher frequency. Because the horizontal scan rate of a VGA monitor is fixed near 31.5 kHz, increasing the pixel clock allowed 360 visible pixels to fit into a single horizontal scanline rather than the default 320, all without driving the monitor outside of its safe sync window.

Unchaining VGA Memory

Standard Mode 13h used a hardware feature called "Chain-4," which mapped consecutive bytes to four interleaved internal 64 KB memory planes. While Chain-4 simplified programming by providing a linear memory layout, it restricted the programmer to 64 KB of accessible display memory, making a 360x480 frame buffer impossible since a single 256-color screen at that resolution requires 172,800 bytes.

To accommodate this data, coders unchained the video memory—a technique popularized in custom "Mode X" implementations:

  1. They accessed the Sequencer Register (0x3C4) and set the Memory Mode Register (index 0x04) bit 3 to zero, disabling Chain-4.
  2. They reconfigured the Graphics Controller (0x3CE) Read and Write Modes to planar access.
  3. They unlocked full access to all 256 KB of VGA RAM.

In this unchained planar setup, four sequential horizontal pixels were split across four separate memory planes at the same memory address. Writing a full 360x480 image required programmers to select planes using the Map Mask register (0x3C4, index 0x02), distributing the 172,800 bytes across the available 262,144 bytes of video RAM with memory to spare for page flipping.

Reprogramming the CRTC for 480 Scanlines

To achieve 480 vertical lines, coders bypassed the default scan-doubling mechanics used by 200-line modes. In 320x200 modes, the VGA hardware draws each scanline twice to fill out a 400-line field. Demoscene developers disabled this behavior:

  1. Unlock CRTC Registers: Bit 7 of the Vertical Sync End register (index 0x11 on port 0x3D4) was cleared to enable write access to the write-protected timing registers.
  2. Disable Scan Doubling: The Maximum Scan Line register (index 0x09) had its cell-height bits cleared to 0, configuring the display to single-scan mode so every hardware scanline displayed unique pixel data.
  3. Set Display Timings: The Vertical Total, Vertical Retrace Start/End, and Vertical Display End registers were reconfigured to match the 480-line active display timings used by standard 640x480 60 Hz modes (Mode 12h).

Achieving Square Pixels and Stability

Combining a 360-pixel horizontal clock with a 480-line single-scan vertical refresh created an exact 3:4 pixel ratio on a standard 4:3 CRT monitor. This gave developers perfectly square pixels—a massive advantage over the stretched pixels of Mode 13h (320x200), eliminating distortion when rendering 3D transformations, vector shapes, and circular graphics.

Because the timing signals precisely mimicked standard 31.5 kHz horizontal and 60 Hz vertical sync conventions, the hardware modification was completely invisible to the CRT monitor itself. The monitor continued operating within standard electrical parameters while the VGA card generated a richer, sharper 256-color image than standard PC BIOS routines ever officially supported.
