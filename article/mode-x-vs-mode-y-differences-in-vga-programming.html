Mode X vs Mode Y: Differences in VGA Programming

During the MS-DOS era of PC game development, programmers bypassed standard BIOS routines to extract maximum performance and flexibility from the Video Graphics Array (VGA) hardware. While the standard Mode 13h offered an easy-to-use 320x200 resolution with 256 colors, it locked developers into a linear 64 KB memory model that wasted three-quarters of the VGA's 256 KB video memory. Mode Y and Mode X emerged as the two primary unofficial "planar" 256-color modes designed to overcome these limitations. The fundamental differences between them lie in their vertical resolution, pixel aspect ratios, available video pages, and CRT controller configurations.

Resolution and Aspect Ratio

The most noticeable difference between the two modes is vertical resolution:

  • Mode Y maintains the native 320x200 resolution of Mode 13h. Because standard CRT monitors have a 4:3 display aspect ratio, rendering 200 scanlines across the vertical axis results in non-square, tall rectangular pixels (an aspect ratio of roughly 1:1.2). Drawing circles or rotating sprites in Mode Y required scaling calculations to prevent distortion.
  • Mode X, popularized by Michael Abrash in 1991, reprogrammed the VGA's display timings to produce a 320x240 resolution. When displayed on a standard 4:3 monitor, 320x240 yields perfectly square pixels (1:1 aspect ratio). This eliminated aspect-ratio correction math, drastically simplifying 2D rotations, line-drawing algorithms, and 3D projection math.

CRTC Configuration and Complexity

Mode Y was historically the stepping stone toward Mode X. Setting up Mode Y requires minimal register manipulation:

  1. Initialize standard Mode 13h via BIOS interrupt 10h.
  2. Disable the sequencer's "Chain-4" mode to expose planar memory.
  3. Disable odd/even host memory addressing and turn off the CRTC's double-word addressing mode.

Mode X requires all the steps used for Mode Y, plus a complete reconfiguration of the CRT Controller (CRTC) vertical timing registers. To display 240 active scanlines instead of 200, the programmer must alter vertical total, vertical retrace start/end, vertical display end, and start blanking registers. It also switches the display from a 400-line frame (where 200 scanlines are doubled) to a true 480-line frame (where 240 scanlines are doubled), which changes the monitor's vertical scan rate from 70 Hz down to 60 Hz.

Memory Footprint and Page Flipping

Both modes unchain the VGA's 256 KB RAM into four parallel 64 KB planes, enabling hardware-assisted writes via the VGA's write latches. However, the difference in resolution impacts frame buffer sizing and page availability:

  • Mode Y (320x200): A single frame requires 64,000 bytes (16,000 bytes per plane). In a 256 KB memory space (65,536 bytes per plane), developers could fit four complete display pages with memory left over. This made quad-buffering or triple-buffering with off-screen sprite caches trivial to implement.
  • Mode X (320x240): A single frame requires 76,800 bytes (19,200 bytes per plane). Within 256 KB, this allows for three full display pages (230,400 bytes total), leaving 25,600 bytes (6,400 bytes per plane) of off-screen memory. While sufficient for smooth double-buffering, it left less room for multiple backbuffers than Mode Y.

Practical Application

Mode Y was ideal for games that prioritized maximum animation buffering and raw frame rendering speed, as rendering 64,000 pixels took less CPU time than rendering 76,800 pixels on slower 286 and 386 processors. Mode X became the industry standard for high-end DOS action games and raycasters (such as id Software's Wolfenstein 3D engine developments) because square pixels made geometry mathematically cleaner and the extra 40 lines provided a sharper presentation.
