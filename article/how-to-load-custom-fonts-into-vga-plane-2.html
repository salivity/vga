How to Load Custom Fonts into VGA Plane 2

Loading custom font bit patterns into Video Graphics Array (VGA) plane 2 memory space requires reconfiguring the VGA hardware registers to expose plane 2 to CPU memory writes, copying the glyph bitmaps, and restoring the registers to standard text mode operation. In standard VGA text modes (such as mode 03h), character generator patterns reside exclusively in bit plane 2 at memory segment 0xA000:0000. Because text mode normally uses odd/even addressing across plane 0 (character codes) and plane 1 (attributes) located at 0xB800:0000, direct access to plane 2 requires manipulating the Sequencer and Graphics Controller registers to bypass the default text rendering pipeline.

Step 1: Reconfigure the Sequencer

To isolate plane 2 for CPU writes, the Sequencer must be programmed to direct memory access specifically to that plane and disable odd/even memory addressing.

  1. Issue a Synchronous Reset: Write index 0x00 with data 0x01 to the Sequencer registers (Index port 0x3C4, Data port 0x3C5) to safely alter clocking and memory settings.
  2. Set the Plane Write Mask: Write index 0x02 (Map Mask Register) with value 0x04 (bit 2 set). This specifies that write operations to video memory only affect plane 2.
  3. Disable Odd/Even Addressing: Write index 0x04 (Sequencer Memory Mode) with value 0x07. Setting bit 2 disables odd/even addressing, allowing sequential linear access across video memory, while bit 1 enables extended memory.
  4. Clear the Reset: Write index 0x00 with data 0x03 to resume normal sequencer operation.

Step 2: Configure the Graphics Controller

The Graphics Controller must be configured to map video memory linearly starting at segment 0xA000:0000 rather than the traditional text buffer segment 0xB800:0000.

  1. Disable Odd/Even Addressing: Write index 0x05 (Graphics Mode Register) to port 0x3CE with value 0x00 sent to port 0x3CF. This puts the controller in standard write mode 0 and clears the odd/even bit.
  2. Remap Memory to 0xA000:0000: Write index 0x06 (Miscellaneous Graphics Register) with value 0x04. This changes the base CPU memory map address from 0xB8000 (text mode default) to 0xA0000 (64 KB linear map) and disables odd/even addressing.

Step 3: Copy the Glyph Patterns to Video Memory

Once plane 2 is mapped sequentially to CPU address space at 0xA000:0000, the custom font data can be transferred using standard memory copy instructions (such as REP MOVSB in x86 assembly).

  • Slot Allocation: VGA font slots allocate 32 bytes per character, regardless of the active character height (for example, 8x8, 8x14, or 8x16 fonts).
  • Glyph Storage: For an 8x16 font, write the 16 bytes of the bitmap sequentially, followed by 16 bytes of zero-padding before advancing to the next character index.
  • Font Blocks: Standard VGA supports multiple font blocks (character sets):
    • Block 0: Base address 0xA000:0000
    • Block 1: Base address 0xA000:4000 (offset 16 KB)
    • Block 2: Base address 0xA000:8000 (offset 32 KB)
    • Block 3: Base address 0xA000:C000 (offset 48 KB)

Iterate through the custom font array and write up to 256 characters (8,192 bytes total per character set) directly to the target block offset.

Step 4: Restore Standard Text Mode Settings

After the copy is complete, the registers must be restored to resume normal text display generation:

  1. Restore the Sequencer:
    • Write index 0x00, value 0x01 (Synchronous Reset).
    • Write index 0x02, value 0x03 (Enable write access to planes 0 and 1).
    • Write index 0x04, value 0x03 (Restore odd/even addressing and standard text mode memory configuration).
    • Write index 0x00, value 0x03 (End Reset).
  2. Restore the Graphics Controller:
    • Write index 0x05, value 0x10 (Restore odd/even addressing in mode register).
    • Write index 0x06, value 0x0E (Map memory back to segment 0xB800:0000 for color text modes).

BIOS Alternative

For systems running in real mode or virtual 8086 mode, the VGA BIOS provides interrupt 10h, service AX = 1100h, which automatically executes the above sequence. Supplying ES:BP with the pointer to the user font table, CX with the number of glyphs, DX with the character offset, BL with the font block, and BH with the bytes per character performs the register reconfiguration, memory copy to plane 2, and register restoration automatically.
