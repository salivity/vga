VGA Write Mode 2 for Fast Pixel Plotting

During the late 1980s and early 1990s, PC game developers faced severe performance bottlenecks when drawing graphics in planar Video Graphics Array (VGA) and Enhanced Graphics Adapter (EGA) 16-color display modes. VGA Write Mode 2 provided an architectural hardware shortcut, enabling programmers to write single 4-bit color values across all four memory planes in a single memory access cycle. This technique was crucial for early 3D flight simulators, vector-based adventure game engines, and high-resolution strategy games that required fast Bresenham line drawing, rapid polygon rasterization, and single-pixel plotting without the severe overhead of standard planar read-modify-write operations.

The Planar Architecture Problem and Write Mode 2

Standard 16-color graphics modes, such as the standard Mode 12h (640x480 at 16 colors) and Mode 0Eh (320x200 at 16 colors), do not arrange pixels sequentially in memory. Instead, they organize display memory across four distinct hardware bit planes, where each plane represents one bit of a pixel's 4-bit palette index.

Under default writing modes (Write Mode 0), updating a single pixel requires setting up the VGA hardware sequencer or running four distinct CPU read-modify-write operations to change that pixel's bit in each plane. This process saturated the slow ISA bus, causing unplayable frame rates in dynamic games.

VGA Write Mode 2 solves this by reconfiguring the VGA Graphics Controller:

  • The CPU writes an 8-bit byte to display memory, but the hardware treats bits 0–3 as the 16-color palette index.
  • The hardware automatically routes each bit of this color index to its respective plane (Bit 0 to Plane 0, Bit 1 to Plane 1, etc.).
  • By programming the Bit Mask Register, developers could isolate a single pixel position within the targeted byte.
  • A single memory write immediately plots the complete color of the pixel, reducing the bus transactions required for individual pixel updates by up to 75%.

Sierra On-Line's SCI0 Engine

One of the most widespread commercial deployments of fast pixel and vector plotting was in Sierra On-Line’s SCI (Sierra's Creative Interpreter) engine, specifically during the SCI0 era (King's Quest IV, Space Quest III, and Leisure Suit Larry II).

Sierra’s artists did not store background screens as raw raster bitmaps to conserve floppy disk space; instead, backgrounds were stored as lists of vector drawing commands, lines, and flood fills. The runtime engine reconstructed these backgrounds dynamically by drawing thousands of vector lines and boundary-fill seeds. Implementing Write Mode 2 allowed Sierra's engine to execute its Bresenham line-drawing and boundary-fill plotting routines rapidly, minimizing loading times as scenes were drawn into the backbuffer.

Early 3D Flight Simulators and Wireframe Renderers

Before the adoption of 256-color linear Mode 13h, wireframe and flat-shaded 3D simulators operated primarily in 16-color EGA or VGA modes to maintain higher resolutions like 640x350 or 640x480.

  • SubLOGIC and Microsoft Flight Simulator (3.0 and 4.0): To achieve usable refresh rates while drawing dynamic horizons, runway markings, and instrument needles, these flight simulators utilized Write Mode 2 for vector rendering.
  • MicroProse Combat Simulators: Early iterations of combat simulators (such as F-19 Stealth Fighter and F-15 Strike Eagle II) running in 16-color modes relied on Write Mode 2 to accelerate the drawing of vector HUDs, structural cockpit frames, and distant wireframe aircraft models.

For arbitrary lines (where consecutive pixels rarely share the same byte address), Write Mode 2 eliminated the need to swap active write planes constantly between pixel coordinates.

Polygon Fillers and Boundary Tracing

In flat-shaded polygon rendering, the leftmost and rightmost edges of horizontal polygon scanlines rarely align neatly to 8-pixel byte boundaries.

Renderers popularized by graphics programmers like Michael Abrash utilized Write Mode 2 to handle the non-aligned boundary edges of polygons:

  1. The engine used Write Mode 2 to plot the partial odd pixels at the start of a horizontal span with a single write using a customized bit mask.
  2. The solid center of the horizontal span was filled using fast 32-bit CPU writes in Write Mode 0 or latch-copying in Write Mode 1.
  3. The terminating boundary pixels were closed off using Write Mode 2 with a final bit mask.

This hybrid approach allowed early software 3D renderers running in 640x480 16-color environments to avoid visual artifacts and maximize throughput over the ISA bus.

High-Resolution Strategy and Simulation Games

Titles like SimCity (running in high-resolution 640x480 16-color Mode 12h) used Write Mode 2 for interactive UI elements. Drawing mouse cursors, animated selection boxes, network power lines, and transit tracks over existing terrain maps required fast single-pixel modification. By setting the color once and simply updating the Bit Mask and destination byte, these games updated dynamic map layers smoothly without freezing the game's simulation loop.
