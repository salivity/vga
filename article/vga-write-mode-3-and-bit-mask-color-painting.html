VGA Write Mode 3 and Bit Mask Color Painting

VGA Write Mode 3 streamlines color painting operations by repurposing the CPU data bus to deliver bit masks directly through memory writes rather than slow I/O port updates. In standard VGA operations, drawing complex shapes or text with specific colors requires constant, costly reconfigurations of internal controller registers to isolate individual pixels. Write Mode 3 eliminates this bottleneck by pairing a fixed foreground color with direct, memory-driven masking, making patterned fills, font rendering, and masked sprite blitting substantially faster and simpler to implement.

The Bottleneck of Conventional Write Modes

In standard planar VGA modes (such as 640x480 16-color Mode 12h), display memory is divided into four parallel bit planes representing the color components of each pixel. To modify a subset of pixels within a byte without disturbing adjacent pixels, the hardware uses a Bit Mask Register (Graphics Controller Index 08h).

In Write Mode 0 or Write Mode 2:

  1. The CPU must read the target video memory to load the internal VGA latches with existing background data.
  2. To apply a unique pixel pattern (such as the edge of a polygon or a character glyph), the CPU must execute an I/O instruction (OUT DX, AL) to update the Bit Mask Register through I/O ports 0x3CE and 0x3CF.
  3. The CPU writes the color data to the target video memory address.

Because I/O bus cycles on the x86 architecture are significantly slower than standard memory writes, updating the Bit Mask Register repeatedly—often once per byte across multiple scanlines—creates a severe performance bottleneck.

How Write Mode 3 Operates

Write Mode 3 fundamentally alters the role of the data byte sent across the CPU bus during a video memory write. Instead of treating the CPU byte as pixel color data, the VGA hardware automatically routes this byte directly into the bit mask logic.

Under Write Mode 3, the hardware pipeline executes the following sequence during a single memory write:

  • Mask Generation: The byte written by the CPU is bitwise ANDed with the contents of the existing Bit Mask Register. When the Bit Mask Register is set to 0xFF (all bits enabled), the CPU write byte acts directly as the 8-pixel mask.
  • Color Source: The color to be drawn does not come from the CPU write. Instead, it is drawn directly from the Graphics Controller's Set/Reset Register (Index 00h), where a 4-bit color value (one bit per plane) has been pre-configured.
  • Latch Combination: For any bit set to 1 in the CPU's mask, the corresponding bit in each plane receives the value defined in the Set/Reset Register. For any bit set to 0, the hardware preserves the original pixel data currently held in the VGA's internal read latches.

Simplifying the Painting Pipeline

This architectural change simplifies software rendering loops down to a minimal set of instructions:

  1. Pre-set the Color: The application writes the desired 4-bit foreground color to the Set/Reset Register once before beginning the drawing loop.
  2. Read to Latch: The CPU reads the target video address (e.g., using MOV AL, [ES:DI]) to populate the VGA latches with the existing background pixels across all four planes.
  3. Direct Mask Write: The CPU writes the pixel mask byte directly to the same address (e.g., using MOV [ES:DI], AL or STOSB).

Because the mask is supplied as a standard memory write rather than an I/O operation, rendering loops can stream masks straight out of system RAM or font tables using fast string instructions without touching the I/O ports again. This reduces bus latency, reduces instruction counts per pixel group, and drastically simplifies the logic required to draw transparent sprites, anti-aliased text, and arbitrary vector geometry.
