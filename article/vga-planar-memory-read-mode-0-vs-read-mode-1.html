VGA Planar Memory: Read Mode 0 vs Read Mode 1

In Video Graphics Array (VGA) planar graphics modes, video RAM is divided across four parallel memory planes (Planes 0 through 3), mapping multiple bits per pixel across the same physical address space. Because a standard 8-bit CPU bus cycle can only access one byte at a time, the VGA Graphics Controller employs two distinct read methods: Read Mode 0 and Read Mode 1. Read Mode 0 retrieves the raw byte data directly from a single user-selected plane, whereas Read Mode 1 compares pixels across all four planes simultaneously using hardware registers, returning a bitmask of matching pixels directly to the CPU.

VGA Planar Memory Architecture

Standard VGA 16-color modes (such as standard Mode 12h: 640x480 at 16 colors) arrange memory into four 64 KB planes. A single byte address across the four planes addresses 8 horizontal pixels, where each pixel's 4-bit color value is assembled from one bit out of each of the four planes:

  • Plane 0: Blue / Low Intensity
  • Plane 1: Green
  • Plane 2: Red
  • Plane 3: High Intensity

The Graphics Controller handles how the CPU interacts with these four layers, switching between Read Mode 0 and Read Mode 1 via bit 3 of the Graphics Mode Register (Index 05h).

Read Mode 0: Plane Selection

Read Mode 0 is the default and most straightforward read method. In this mode, a memory read operation fetches the raw 8-bit data stored in one designated plane at the target memory address.

  • Configuration: Controlled by the Read Map Select Register (Graphics Controller Index 04h). Bits 0 and 1 specify which plane (0, 1, 2, or 3) is connected to the CPU data bus.
  • Operation: When the CPU reads from a video memory address, the hardware routes the exact 8-bit value from the selected plane directly to the processor.
  • Application: Read Mode 0 is typically used for general-purpose pixel reading, reading back font definitions in text modes, and standard software blitting routines where data from each plane is copied sequentially to system RAM.

To read the complete color of all 8 pixels at an address using Read Mode 0, the CPU must perform four separate read cycles, reprogramming the Read Map Select Register between each operation.

Read Mode 1: Hardware Color Comparison

Read Mode 1 bypasses direct byte retrieval to provide hardware-accelerated color matching across all four planes in a single read cycle.

  • Configuration: Configured using the Color Compare Register (Index 02h) and the Color Don't Care Register (Index 07h). The Color Compare Register holds a 4-bit target color value, while the Color Don't Care Register determines which planes are included in or excluded from the evaluation.
  • Operation: When the CPU executes a read at a memory address, the VGA hardware evaluates all 8 pixels located at that byte offset across all four planes in parallel. For each pixel position (bits 0 through 7), the 4-bit color is matched against the Color Compare Register. If the bits match on all planes marked active by the Color Don't Care Register, the corresponding bit in the returned byte is set to 1. If they do not match, the bit is set to 0.
  • Application: Read Mode 1 drastically reduces CPU overhead for common raster algorithms, including:
    • Collision Detection: Checking whether any non-background color pixels occupy a specific coordinate.
    • Transparency / Chroma Keying: Quickly locating transparent pixels without manually unpacking color planes in software.
    • Flood Fill and Boundary Tracing: Rapidly scanning large areas for specific edge or fill boundaries.

Key Differences

Feature Read Mode 0 Read Mode 1
Output Data Raw byte from a single plane 8-bit match mask across all four planes
Planes Accessed Single plane (selected by Read Map Select) All active planes simultaneously
Primary Registers Read Map Select Register (04h) Color Compare (02h), Color Don't Care (07h)
CPU Workload Higher for color logic (requires 4 reads) Minimal (hardware handles the comparison)
Primary Use Case Plane-by-plane copying, reading textures Collision detection, mask generation, boundary checks
