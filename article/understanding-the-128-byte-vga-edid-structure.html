Understanding the 128-Byte VGA EDID Structure

Extended Display Identification Data (EDID) is a standardized 128-byte data structure that enables a computer monitor to communicate its specifications and display capabilities to a host graphics adapter. When using a Video Graphics Array (VGA) connection, this data is stored in an onboard EEPROM chip and retrieved using the I2C-based Display Data Channel (DDC2B) protocol over VGA pins 12 (SDA) and 15 (SCL). This article provides a direct breakdown of the 128-byte memory map, detailing the exact layout and purpose of each data block defined by the VESA EDID standard.

The VGA Hardware Interface

The host system communicates with the monitor's EEPROM (commonly mapped at I2C address 0x50) using two dedicated lines on the standard 15-pin D-sub VGA connector:

  • Pin 12 (SDA): Serial Data line for bidirectional I2C data transfer.
  • Pin 15 (SCL): Serial Clock line driving the I2C bus timing.
  • Pin 9 (+5V DC): Provides power to the EEPROM even when the monitor is turned off.
  • Pin 5/10 (Ground): Provides common return paths for signaling.

The 128-Byte Base EDID Structure

The 128-byte base structure defined in EDID 1.3 and 1.4 is divided into ten functional blocks:

1. Header (Bytes 0–7)

The first 8 bytes contain a fixed synchronization pattern used by the host to confirm a valid EDID block. The byte sequence is always: 00 FF FF FF FF FF FF 00

2. Vendor and Product Identification (Bytes 8–17)

This 10-byte block uniquely identifies the monitor:

  • Bytes 8–9: Manufacturer ID (A compressed 3-character uppercase ASCII code, formatted as three 5-bit values).
  • Bytes 10–11: Product ID code (16-bit integer, little-endian).
  • Bytes 12–15: 32-bit serial number (Optional; set to zero if the serial number is stored as a text descriptor).
  • Byte 16: Week of manufacture (1–54) or model year flag.
  • Byte 17: Year of manufacture (Value plus 1990).

3. EDID Version and Revision (Bytes 18–19)

These bytes indicate the specific standard version the structure conforms to:

  • Byte 18: Version number (Typically 0x01 for EDID 1.x).
  • Byte 19: Revision number (e.g., 0x03 for EDID 1.3, 0x04 for EDID 1.4).

4. Basic Display Parameters and Features (Bytes 20–24)

These 5 bytes define hardware characteristics:

  • Byte 20 (Video Input Definition): Bit 7 specifies analog (set to 0 for VGA), with remaining bits defining signal voltage levels, sync types (separate, composite, sync-on-green), and setup levels.
  • Byte 21: Maximum horizontal image size in centimeters (or aspect ratio in EDID 1.4).
  • Byte 22: Maximum vertical image size in centimeters (or aspect ratio in EDID 1.4).
  • Byte 23: Display gamma (Calculated as (Value + 100) / 100, typically yielding 2.2).
  • Byte 24 (Feature Support): Bitmask indicating power management modes (Standby, Suspend, Active Off), color encoding formats (RGB, YCbCr), and preferred timing mode flags.

5. Color Characteristics (Bytes 25–34)

A 10-byte block containing 10-bit CIE 1931 xy coordinates for the display's color space:

  • Bytes 25–28: Low-order fractional bits for Red, Green, Blue, and White points.
  • Bytes 29–34: High-order 8 bits for Red X/Y, Green X/Y, Blue X/Y, and White X/Y.

6. Established Timings (Bytes 35–37)

A 3-byte bitfield representing legacy standard display resolutions supported by the monitor, such as 640×480 @ 60Hz, 800×600 @ 60Hz, and 1024×768 @ 60Hz.

7. Standard Timings (Bytes 38–53)

Eight 2-byte descriptors (16 bytes total) that specify up to eight non-legacy standard display modes:

  • Byte 1: Horizontal active pixel count divided by 8, minus 31 (e.g., (Width / 8) - 31).
  • Byte 2: Image aspect ratio (16:10, 4:3, 5:4, 16:9) and vertical refresh rate (field value plus 60 Hz).
  • Unused fields are padded with 0x01 0x01.

8. Detailed Timing Descriptors (Bytes 54–125)

This section consists of four 18-byte blocks (72 bytes total).

  • First Block (Bytes 54–71): Almost always the Preferred Timing Mode (native resolution). It defines the pixel clock (in 10 kHz units), horizontal/vertical active pixels, blanking intervals, sync offsets, sync pulse widths, and sync polarity.
  • Remaining Blocks (Bytes 72–125): Can specify additional detailed timings or display descriptor data. When used as descriptors, the first two bytes are 0x00 0x00, followed by a descriptor type byte such as:
    • 0xFF: Display Serial Number (ASCII text).
    • 0xFC: Display Product Name / Model String (ASCII text).
    • 0xFD: Display Range Limits (Minimum and maximum vertical/horizontal frequencies and maximum pixel clock).
    • 0xFB: Color Point Data.

9. Extension Block Count (Byte 126)

Indicates the number of additional 128-byte extension blocks (such as CEA-861 for HDMI/audio extensions or VESA DisplayID) that follow this base block. For pure legacy VGA displays, this is typically 0x00.

10. Checksum (Byte 127)

A 1-byte checksum calculated such that the arithmetic sum of all 128 bytes in the EDID block modulo 256 equals 0x00. If the sum does not equal zero, the host treats the EDID block as corrupted.
