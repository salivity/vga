What Causes VGA Split Screen Shake on Late Updates

Split-screen shaking in Video Graphics Array (VGA) programming occurs when register modifications miss the critical timing window of the raster beam, specifically during horizontal blanking intervals. The VGA hardware relies on exact hardware counters and register comparisons on every scanline to divide the display. When software updates critical registers—such as the Line Compare register or the Display Start Address—too late in the scanline cycle, the Cathode Ray Tube Controller (CRTC) fails to process the new values for that intended line. Because execution timing slightly fluctuates between frames due to CPU cycles and system interrupts, the hardware unpredictably alternates between catching and missing this threshold, resulting in a visible, rapid vertical or horizontal jitter in the bottom half of the screen.

The VGA Split-Screen Hardware Mechanism

The VGA CRTC generates display addresses sequentially as the electron beam traverses the screen from top to bottom, left to right. To achieve a hardware split screen, the VGA provides a feature controlled by the Line Compare register (CRTC Index 18h, extended by overflow bits in Index 07h and 09h).

As the monitor draws each scanline, an internal vertical counter increments. When this counter equals the value stored in the Line Compare register, the CRTC automatically resets its internal memory address counter back to zero. This causes the monitor to begin drawing the remainder of the frame from the start of video memory, creating two distinct visual areas: a scrolling top window and an independent, usually static, bottom window.

The Race Condition of Late Updates

Shaking or jitter occurs primarily when developers attempt dynamic effects on the bottom section, such as scrolling the lower split or moving the split line dynamically. Because standard VGA lacks a fully shadow-buffered register architecture for all CRTC parameters, changes written to the I/O ports immediately affect the internal hardware state or latch at the next immediate horizontal clock.

If the CPU writes an updated Line Compare value or Display Start Address while the electron beam is already processing the target scanline, a race condition occurs:

  1. Missed Scanline Comparison: The internal comparator checks the scanline counter against the Line Compare register at a specific clock cycle during the horizontal blanking (HBlank) interval or at the start of the active display line. If the write arrives a fraction of a microsecond after this check, the comparator does not fire for that scanline.
  2. Address Counter Desynchronization: Because the match failed, the address counter does not reset to zero. The CRTC continues reading sequential display memory from the top screen instead of resetting for the bottom screen, or it delays the reset until an unintended line.
  3. Partial Latching: If modifying multi-byte registers (such as Start Address High at Index 0Ch and Start Address Low at Index 0Dh) to pan the lower screen, a late write often results in the CRTC reading the new high byte while retaining the old low byte for that single frame.

Non-Deterministic Frame Timing and Jitter

The human eye perceives this timing miss as "shaking" rather than a permanent glitch because the CPU timing relative to the CRT beam drifts. DRAM refresh cycles, CPU instruction caching, and unmasked system interrupts cause tiny variations in how fast the software completes its register-writing loop.

In one video frame, the CPU finishes the register update just before the raster beam reaches the trigger scanline, displaying the lower screen at the correct offset. In the subsequent frame, a minor delay causes the write to land just after the beam passes, causing the screen to render with the old offset or skip the address reset entirely. The rapid alternation between the correct state and the missed-timing state across 60 or 70 Hz refresh cycles creates high-frequency vibration and shaking in the lower split screen.

Preventing Split-Screen Instability

To eliminate the shake, register writes must strictly synchronize with the raster beam. Developers avoid this issue by polling Input Status Register 1 (port 03DAh) to detect the exact start of the Horizontal Blanking interval immediately preceding the split line, or by using cycle-timed interrupt service routines triggered by horizontal interrupts. Ensuring that all relevant CRTC index and data pairs are completely written before the active display line begins guarantees that the hardware comparator reliably catches the update on every single frame.
