VGA Memory Banking: Accessing VRAM Beyond 256 KB

The original IBM Video Graphics Array (VGA) standard was fundamentally constrained by the IBM PC real-mode architecture to a maximum of 256 KB of video memory mapped across a small physical address space. To overcome this ceiling and deliver higher resolutions and deeper color depths, third-party Super VGA (SVGA) clone manufacturers introduced memory banking mechanisms. Memory banking—also referred to as bank switching or paging—allowed the graphics card to map a small, movable aperture of a much larger physical video buffer into the conventional memory space accessible to the central processing unit (CPU).

The Real-Mode Memory Barrier

The IBM PC real-mode memory architecture allocated only a 128 KB block between addresses A0000h and BFFFFh for video hardware. Standard VGA typically used a 64 KB window spanning A0000h to AFFFFh for graphics modes.

Standard VGA achieved 256 KB capacity within this 64 KB aperture by dividing memory into four parallel 64 KB planes (Planes 0 through 3). The CPU addressed all four planes at the same memory location simultaneously, relying on internal VGA hardware registers—such as the Sequencer and Graphics Controller—to dictate which planes were read from or written to. While this allowed 16-color modes to leverage all 256 KB efficiently, it reached an absolute limit when displaying linear, high-color graphics. A mode requiring 256 colors (8 bits per pixel) or true color (24 bits per pixel) at resolutions like 800x600 or 1024x768 quickly exceeded both the 256 KB physical limit and the 64 KB CPU access window.

How Memory Banking Operated

Memory banking solved this issue by decoupling the CPU's accessible address window from the physical layout of the video RAM (VRAM).

Instead of requiring the CPU to map the entire video frame buffer into system memory simultaneously, the SVGA card divided its total VRAM (such as 512 KB, 1 MB, or more) into smaller segments, or "banks," typically 64 KB in size. The graphics controller acted as an intermediary translation layer:

  1. Window Mapping: The graphics card exposed a 64 KB aperture at A0000h to the system bus.
  2. Bank Selection: The software communicated with the graphics chipset via extended I/O ports or internal registers to specify which 64 KB slice of physical VRAM should be routed to that aperture.
  3. Offset Translation: When the CPU issued a read or write operation to an address within A0000h–AFFFFh, hardware logic on the graphics board added an offset corresponding to the selected bank's base address in physical VRAM before performing the memory access.

For example, on a card with 1 MB of VRAM, the memory was divided into sixteen 64 KB banks (Banks 0 through 15). To write a pixel located at physical VRAM offset 12000h (within the second 64 KB block), the software would switch the active bank register to Bank 1, and then write to the corresponding address inside the A0000h window.

Advanced Banking Features: Split and Dual Banking

Early banking implementations mapped a single bank for both read and write operations. This caused performance bottlenecks during memory-to-memory block transfers, such as moving a sprite from an off-screen buffer to the active display area in a different bank. The CPU had to repeatedly toggle the bank register back and forth for every read and write cycle.

To eliminate this overhead, advanced SVGA chipsets (such as those from Tseng Labs, Cirrus Logic, and Trident) implemented dual-banking or split-banking architectures:

  • Read and Write Banks: Chipsets provided separate bank registers for read and write cycles. The CPU could read source data mapped to Bank 2 and write target data to Bank 5 without intervening register adjustments.
  • Dual 32 KB Windows: Some implementations split the 64 KB aperture into two separate 32 KB windows (e.g., Window A at A0000h–A7FFFh and Window B at A8000h–AFFFFh), with each window pointed to an arbitrary 32 KB region anywhere in the total VRAM space.
  • Granular Stepping: Certain controllers allowed banking in finer granularities (such as 4 KB or 16 KB boundaries) rather than coarse 64 KB steps, providing smoother access alignment for scanlines.

Standardization via VESA

Because early SVGA manufacturers implemented proprietary I/O registers and access routines for their bank-switching mechanisms, software developers faced severe compatibility issues. A game or graphical application required unique drivers for Tseng Labs ET3000/ET4000, Western Digital/Paradise, Oak Technology, Trident, and Cirrus Logic chipsets simply to handle memory paging.

This fragmentation led to the establishment of the Video Electronics Standards Association (VESA) and the creation of the VESA BIOS Extensions (VBE). The VBE standard abstracted hardware-specific bank switching behind a uniform software interrupt interface: INT 10h, AX=4F05h (VBE Function 05h: CPU Video Memory Control). Software could switch banks reliably across any VESA-compliant graphics card without needing direct knowledge of the underlying proprietary registers, solidifying memory banking as the industry standard method for operating beyond the original 256 KB VGA boundary until the advent of protected mode and linear frame buffer architectures.
